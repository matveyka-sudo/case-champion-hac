# Архитектура
Продукт: [PRODUCT_SPEC.md](PRODUCT_SPEC.md). Четыре вида анализа, без старых regular/medical.
| Путь | Владелец | Граница |
|---|---|---|
| frontend/ | FRONTEND | Активный React/Vite проект, карта, формы, исходные метрики, состояния |
| apps/api/ | BACKEND | HTTP, jobs, worker, кеш, миграции |
| packages/contracts/ | BACKEND | Независимые DTO, схемы, единицы и статусы |
| packages/engine/ | ML1 | Временные цепочки и сценарии; индекс только после согласования |
| packages/data_pipeline/, data/, ml/ | ML2 | Источники, геометрии, население, расписания, грузовые узлы, QA |
| packages/assistant/ | BACKEND | Объяснение сохранённых результатов и разрешённые сценарии |
| infra/, .github/, config/ | DEVOPS | Окружение, CI, конфигурация и выпуск |

frontend/ содержит более новый Vite starter, добавленный командой. Он сохраняется и является единственной активной точкой frontend-разработки. apps/web/ сохранён как исторический подготовительный manifest; перенос нужных зависимостей выполняется отдельно с FRONTEND, без установки второго приложения.
Python workspace, lock и PostgreSQL 17 сохраняются. API/worker ещё не реализованы. Большие задания выполняются worker; кеш включает параметры, версии источников, геометрию, профиль и методику. RAG используется для текстового контекста; численные вычисления выполняются по структурированным данным. Ключи API только на сервере.
Сценарное изменение расписания требует локальной изменяемой модели или поддерживающего API; внешний готовый маршрут не позволяет доказать эффект сдвига рейса. База и сценарий неизменяемы, ухудшения также показываются.
