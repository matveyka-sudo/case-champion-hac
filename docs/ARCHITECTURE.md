# Архитектура атласа A2

Атлас сравнивает три независимых профиля и позволяет пассажиру проверить поездку по заданным ограничениям. P0 включает F01–F09. Канонические интерфейсы описаны в [спецификациях](../packages/contracts/specs/README.md). Границы ролей следуют ТЗ 1.1, с. 7, 11–13 и 16–17.

| Поток | Владелец и граница |
| --- | --- |
| Источники → адаптеры и QA → принятый SnapshotBundle и evidence | ML2, `packages/data_pipeline`. Сохраняет immutable raw и нормализованные снимки. Публикует только после QA и явно описывает область полноты. |
| AcceptedData → маршруты, оценки, сравнения | ML1, `packages/engine`. Одно детерминированное ядро для всех профилей. Загруженные данные получает аргументом. |
| DTO и валидаторы | BACKEND, `packages/contracts`. Общие схемы и доменные ошибки независимы от HTTP, хранилища, engine и LLM. |
| API → jobs → worker → run | BACKEND, `apps/api`. API валидирует и регистрирует тяжёлый запрос, отвечает 202. Один worker забирает job, вызывает engine и публикует результат с версиями. UI опрашивает job каждые 2 с. |
| Один продуктовый агент → ограниченные tools | BACKEND, `packages/assistant`. Tools используют те же валидаторы и доменные функции, что REST. При сбое модели UI продолжает работать через API и показывает сохранённые результаты. |
| UI | FRONTEND, `apps/web`. React, TypeScript, HTTP-клиент из OpenAPI, карта, формы, три профиля и provenance. |
| Выпуск | DEVOPS. Версии, конфигурация, CI, запуск и приёмочные ворота. |

Тяжёлый расчёт выполняет один worker, отдельно от обработки HTTP. Для пилота API и worker — точки запуска одного backend в монорепозитории. Дополнительные брокеры и вычислительные стеки не нужны для подготовленного окружения. BACKEND определит получение job и атомарную публикацию результата, включая idempotency и hard timeout. DEVOPS добавит фактические команды и конфигурацию запуска после handoff entrypoints.

Рекомендация R для ML1 — временной граф событий рейсов и проверенных пеших переходов. При поиске сохраняются альтернативы по времени, пересадкам и активным ограничениям. Готовый GTFS-движок оценивается после проверки импорта.

## Хранилище и окружение

SQLite на с. 7 ТЗ — инженерная рекомендация R для компактных метаданных. Оставляем совместимый PostgreSQL 17, уже подготовленный в Compose с asyncpg и Alembic. Он хранит каталог принятых версий, jobs, метаданные и результаты. Raw и нормализованные таблицы остаются неизменяемыми файлами, в том числе Parquet. BACKEND использует параметризованный raw SQL через asyncpg и ограниченный пул, SQLAlchemy служит миграциям Alembic. Миграции и worker требуют реализации. Второе хранилище для того же состояния не вводится.

Совместимые manifests и lock-файлы Python/FastAPI и React/TypeScript сохранены. `package = false` относится к подготовительным workspace members без реализации. После появления src-пакета его владелец передаёт DEVOPS способ импорта и зависимости. DEVOPS включает упаковку и обновляет общий `uv.lock` после проверки.

| Проект | Будущий src-layout | Локальные зависимости |
| --- | --- | --- |
| `a2-contracts` | `packages/contracts/src/a2_contracts` | Нет |
| `a2-data-pipeline` | `packages/data_pipeline/src/a2_data_pipeline` | `a2-contracts` |
| `a2-engine` | `packages/engine/src/a2_engine` | `a2-contracts` |
| `a2-assistant` | `packages/assistant/src/a2_assistant` | `a2-contracts`, публичные функции engine через tools |
| `a2-api` | `apps/api/src/a2_api` | `a2-contracts`, `a2-data-pipeline`, `a2-engine`, `a2-assistant` |

Модель, API-доступ и денежный лимит открыты в D4. Параметры задаются будущей конфигурацией, ключ только на backend. Подписка ChatGPT не подтверждает API-доступ или бюджет.
