# A2: замена 2ГИС, пробки, модель и проверенные источники

Исследование от 07.11.2026; решения финализированы 08.11.2026.
Принята архитектура без 2ГИС. Модель — Alice AI LLM Flash (ASSISTANT.md).
Ниже сохранены результаты прошлой проверки источников; они не являются
новым live-тестом и не подтверждают готовность production-адаптеров.
Бесплатные данные и ПО не означают бесплатный сервер или полные расписания.
Обязательные решения ограничений — IMPLEMENTATION.md.

## Принятая архитектура

| Функция | Решение | Граница ответственности |
| --- | --- | --- |
| Карта, здания, дороги, остановки, POI | OSM / региональные выгрузки Geofabrik; PostgreSQL/PostGIS | Карта не подтверждает работу учреждения, собственника или расписание |
| Автомобиль, грузовой подъезд и пешие участки | Самостоятельно размещённый Valhalla | Грузовые ограничения требуют атрибутов; штатная скорость не является наблюдением пробок |
| Общественный транспорт | OTP 2 + проверенные GTFS и собственные импортёры | Метро/электрички требуют своих данных; общий бюджет ожиданий контролирует наш engine |
| Массовые расчёты | Worker, кеш и батчи; R5 изучать только после проверки семантики | Медиана времени по окну не равна поездке в выбранный момент |
| Межгородские пассажирские рейсы | Яндекс Расписания и подтверждённые источники перевозчиков | API с ключом ещё не проверен; не покрывает автоматически городской транспорт и грузовые отправления |
| Пробки | Отдельный поставщик дорожных времён; тестовый кандидат «Квазар» | Нет подтверждённого бесплатного исторического покрытия трёх городов |
| Агент | Alice AI LLM Flash, Yandex AI Studio Chat Completions | Объясняет факты, читает разрешённые tools; формулы выполняет Python |

Модель выбрана пользователем 08.11.2026. Настройки, официальный API,
capability smoke и работа без ключа — ASSISTANT.md. Живой вызов с проектным
ключом не выполнен. Старый кандидат OpenAI больше не используется.
Запросы к картам и массовые матрицы не прогоняются через LLM.

Tools агента — предметные операции чтения accepted bundles,
получения результата и получения предложенного сценария. Запуск проверки
сценария требует пользовательского действия; произвольные URL, SQL и shell
агенту не выдаются. REST-формы должны работать независимо от модели.

## Что именно означают пробки в продукте

1. **Типичная ситуация (`typical`)**: профиль по направленному участку,
   времени суток, дню недели, рабочему/праздничному статусу и сезону. Это
   основной режим для устойчивого анализа территории и сопоставимого рейтинга.
2. **Текущая ситуация (`live`)**: свежий срез вблизи текущего момента.
   Нужны время измерения/публикации и допустимый интервал применения.
3. **Исторический срез (`historical`)**: наблюдения на конкретную прошлую дату.
   Не равен среднему по аналогичным дням.
4. **Расчёт без пробок (`static`)**: дорожная модель без подтверждённых
   наблюдений. Самостоятельный явно обозначенный режим, не скрытый fallback.

Live не переносится на следующие сутки/месяц. Профиль 2021 года не называется
актуальным профилем 2026 года. Если для выбранного режима данных нет,
результат `unknown`; статический расчёт показывается отдельно. Нельзя
сравнивать в общем рейтинге Москву с наблюдениями и другой город без них.

Для имеющих правомерный доступ наблюдений строится профиль времени прохождения
ребра по сопоставимым дням. Минимальную выборку, исключение аномалий,
агрегатор и срок годности следует валидировать на данных, затем версионировать.
Пока этого нет, никакого универсального коэффициента «час пик ×1.5».
Для незнакомых улиц и сезонов возможен отдельный модельный прогноз, но его
точность и перенос между городами сначала проверяются; он не маркируется
наблюдением. Общегородской балл пробок не заменяет скорости участков.

\[
t_e(s_e)=L_e/v_e(s_e),\qquad
s_{e+1}=s_e+t_e(s_e)+t_{turn,e}.
\]

`s_e` — время въезда на конкретный участок, а не только старт всей поездки.
`t_turn` добавляется лишь когда не включено в предоставленное время.
Для длинного участка пересечение временных слотов обрабатывает маршрутизатор.
Замыкания/перекрытия — недоступное ребро, не нулевая скорость с делением на ноль.

Автобусные/трамвайные расписания уже могут учитывать обычные заторы. Умножать
всю длительность по GTFS на автомобильный коэффициент нельзя: это удвоит
задержку и затронет выделенные полосы, остановки и метро. Изменять расписание
можно по согласованной модели задержек или GTFS-RT, затем заново проверять
пересадки. Эталон A использует собственный зафиксированный профиль без
текущих заторов, иначе пробка будет искусственно улучшать нормирование.

Сценарий фиксирует snapshot трафика. После сдвига отправления путь может
попасть в другой временной слот того же профиля; новые текущие данные
не подмешиваются в after. Маршрутный граф обновляется целиком по версии.

## Проверка «Квазара»: реальные HTTP-запросы

Официальная документация: https://api.1traffic.ru/v2/ . Публичный `demo`
предназначен для разработки и тестирования, лимит **1 запрос/с**. Проверка
выполнена последовательно с паузами. Постоянное бесплатное использование,
массовое накопление истории и права на повторное распространение не подтверждены.

Рабочий endpoint: `POST https://api.1traffic.ru/v2/matrix?key=demo`.
Использовать путь **без завершающего слеша**: в проверке вариант со слешем
вернул 307 на HTTP. Снижение защиты до HTTP не использовали.
`sources` и `targets` — массивы объектов lat/lon; `traffic=0/1`, `cartype=auto`.

| Город, проверенная пара координат | traffic=0, с | traffic=1, с |
| --- | ---: | ---: |
| Москва: 55.75,37.61 → 55.78,37.60 | 612 | 699 |
| Калининград: 54.710,20.510 → 54.730,20.500 | 287 | 400 |
| Новороссийск: 44.723,37.769 → 44.700,37.780 | 381 | 383 |

Все шесть ответов — HTTP 200, численные `distance` и `time` в
`sources_to_targets`. Это точечный smoke test, не проверка точности города.
В Москве изменилась и длина выбранного пути: 5.35 → 4.343 км, поэтому разность
времён нельзя называть задержкой на одном и том же маршруте.

В этих ответах отсутствовали время измерения пробок, качество наблюдений и
идентификаторы дорожных рёбер. Ответ даёт ETA пары, **не готовый слой скоростей
для загрузки в Valhalla**. Документированного параметра даты/времени для
типичного/исторического профиля в этом API не обнаружено. Сайт компании
заявляет архив и прогноз для ряда регионов, но покрытие, выдача, условия и
цена архива для наших трёх городов не проверены. Нужен доступ к выборке и
разрешённые условия использования; сообщения поставщику не отправлялись.

## Проверка расписаний: содержимое, а не только ссылки

**Москва.** Скачан ZIP `mdb-3226-202606301640` из Mobility Database (30.06.2026),
68 376 874 байта. Шесть CSV: agency, calendar, routes, stops, stop_times, trips.
877 маршрутов: 841 bus, 35 tram, 1 cable tram по кодам GTFS. Метро и
пригородной железной дороги в этом наборе нет. 17 896 остановок с заполненными
координатами, 224 851 trip, 6 227 078 строк stop_times, 2 100 service calendar.
На 07.11.2026 календарно применимы 399 маршрутов и 52 309 trips — это условие
календаря архива, не подтверждение их актуальности на эту дату.

177 845 строк stop_times ссылаются на отсутствующие trips; 6 400 — на
отсутствующие stops. Есть пустые имена CSV-колонок, нет calendar_dates и shapes.
Календарные интервалы до 2030 года не доказывают свежесть. Строки stop_times
не упорядочены по последовательности, их надо сортировать; подсчёт уменьшений
sequence в порядке файла сам по себе не означает испорченный рейс.
Полный официальный GTFS validator и загрузка в OTP ещё не запускались.
Набор требует карантина/ремонта с отчётом потерь, проверки календарей, покрытия
и дополнительных источников метро/электричек; нельзя объявлять его готовым.

**Калининград.** На официальной странице gortrans39.ru/routes/ найдено 23
ссылки маршрутов. Проверены av1, av11, av14, av15, av16: остановочные времена
встроены в JavaScript; есть `weekdays`, `saturday`, `weekend`. Соответственно
25, 27, 36, 23, 15 именованных остановок. У av1 будние списки имеют 45/46
элементов и несовместимое начало соседних списков. Независимые остановочные
времена нельзя механически соединять по индексу массива. Нужны подтверждённые
направления, идентичность рейсов, сроки действия и праздничные исключения.
Это источник для импортёра и QA, не полный готовый GTFS всех перевозчиков.

**Новороссийск.** Найден канал муниципального перевозчика, но полученная
публичная HTML-страница содержит описание канала без загруженных расписаний.
Получить и проверить полный актуальный набор остановочных расписаний в этой
проверке не удалось. Недоступность сайта/файла не доказывает отсутствие данных.

## Как начать разработку, сохранив требования

Разрабатывать контракт источников, импорт/QA, engine и UI на явно помеченных
тестовых fixtures. Подключать реальные accepted bundles по проверенным
территориям/датам. Не выдавать тестовую выборку за покрытие города.
Полный режим с пробками и точными пересадками считается готовым только после
закрытия пробелов ниже; scope трёх городов и всей РФ остаётся целевым.

1. Для пробок: численный источник истории/типичных профилей, права использования,
   три города, направления, время, map matching либо целостный внешний ETA.
2. Для расписаний: обратные направления, календарные исключения, trip identity,
   метро/электрички, проверка схемы и контрольные маршруты в OTP.
3. Для эталона A: реализовать калибровку рёбер и операции по IMPLEMENTATION.md.
4. Для LLM: настроить ключ/бюджет и прогнать evals на русском, включая пропуски,
   противоречивые документы и запрет запуска сценария до действия пользователя.
