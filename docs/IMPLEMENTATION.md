# План реализации и решения ограничений
Версия 2026-11-08.1. Это обязательная последовательность интеграции, не утверждение о готовом backend.

## Решения первой версии
| Проблема | Исполнимое решение | Результат при нехватке данных |
|---|---|---|
| Отказ от 2ГИС | OSM/Geofabrik + PostGIS, Valhalla для дорог/пешком/грузового подъезда, OTP 2 для GTFS | static-road и walk работают независимо от расписаний |
| Нет полного GTFS трёх городов | ML2 импортирует официальные таблицы/GTFS в единый trip/stop_time/calendar, валидирует; начинает с явно ограниченного пилотного графа | Неизвестные виды не превращать в отсутствие транспорта; частичный ОТ, без полного рейтинга |
| Таблица остановок без trip_id | Не склеивать n-е отправления; использовать только как справку частоты до подтверждения рейсов | Нет ложной сквозной поездки |
| Типичные пробки не найдены бесплатно для всех городов | RoadSpeedProfile из разрешённых наблюдений; static доступен отдельно с первого запуска | typical отключён для неподдержанного места/периода |
| Live Quasar проверялся с demo | Отдельный optional adapter после подтверждения production-условий; pair ETA как целая оценка поездки | Не переносить pair ETA на рёбра Valhalla и не выдавать demo как production |
| Нет годного растра населения | GHSL/WorldPop с годом; при отсутствии — распределить официальный итог по подтверждённой жилой площади в границах территории | Метод estimated; нет жилой площади — population unknown, карта времени остаётся |
| Нет владения POI | Соединение с официальным учрежденческим реестром; спорное в quarantine | Не включать частную клинику в государственную категорию |
| Нет грузовых расписаний/операций | Подтверждённые записи операторов и ручной импорт с URL/датой; movement отдельно | Полный cargo score unknown, инфраструктурный анализ доступен |
| Нет трубы/её характеристик | Верифицированный реестр операторов и узлов; продукт/направление отдельно | Нет карты вымышленных соединений и свободной мощности |
| API даёт только готовый маршрут | Сохранить неизменяемый ответ для базового анализа; сценарий только на редактируемом локальном графе | Предложить объяснение вместо ложной симуляции |
| Огромный расчёт | Worker, пакетные матрицы и кеш; выбранная пара РФ on-demand; графы трёх городов заранее | Прогресс/частичный результат, не зависший HTTP |
| Нет ключа Flash | Шаблонные доказательные объяснения | Остальные экраны и расчёты доступны |

Фактические проверки и ограничения — TRAFFIC_AND_PROVIDERS.md. Наличие open-source движка не равно нулевой цене сервера.

## Пробки: конкретный контракт
RoadSpeedProfile: directed_edge_id, graph_version, speed_kph, weekday_type, local_15min_bin, season, sample_count, observed_period, license, method, confidence.
Typical: медиана наблюдаемых скоростей для одного направления/интервала/типа дня/сезона; минимум 5 разных дней с валидными наблюдениями — инженерный QA-порог v1. Если меньше — unknown, без смешивания направлений или зимы с летом. Время ребра по времени входа на него. Замыкание/закрытие — отдельный флаг, не speed=0.
Маршрут без полного профиля не считается полностью typical. Допускается явно выбранный static run, не гибрид под прежней этикеткой.
Live имеет observed_at и valid_until; если провайдер не сообщает время наблюдения — fetched_at только время получения, уверенность ограничена. Historic требует реального покрытия выбранного момента.
Автобусное расписание уже может включать пробки: не умножать расписанный путь на автомобильный коэффициент. Динамическая корректировка автобуса только отдельной проверенной моделью, метро/электричка не получают дорожный штраф.

## Эталон A: закрытие оставшегося решения
Применяем A, не исторический лучший рейс B. Эталон строится на том же версионированном графе существующих разрешённых связей и совместимых узлов; смешанные пути разрешены.
Новый инженерный профиль v1: road — static/free-flow cost Valhalla с закреплёнными версией и costing options; rail/air/water — минимальное подтверждённое running time конкретного ребра в принятом snapshot, без ожидания отправления. Это калибровка рёбер, а не минимум всей поездки A→B; поисковый алгоритм свободно собирает смешанный эталон.
Для таких рёбер v_ref = длина / running_time. Когда геометрии авиаучастка нет, расстояние по геодезической используется только для записи эффективной скорости, cost остаётся подтверждённым временем; это не реальная траектория.
Necessary operations — подтверждённые минимальные переходы/смены узлов/операции из snapshot. До первого отправления и после последнего прибытия операции не включаются в пассажирский T_path. Внутри цепочки — включаются. Ожидание ближайшего отправления убирается из эталона.
Нет подтверждённого edge cost/transfer minimum — ребро не выдумывается; reference coverage становится partial и индекс предварительный, не полный рейтинг. Unknown не доказывает отсутствие пути. При полном отсутствии допустимого эталона raw времена остаются.
Так не нужны произвольные скорости «по виду транспорта» и горные множители. Профиль не является физическим идеалом: зависит от принятой сети, версии движка и данных. Эти зависимости сохраняются в run.
Если reference хуже фактического пути, применяется согласованный cap 100 и диагностическое REFERENCE_INCONSISTENCY; такой случай требует QA, а не автоматического повышения скорости.
Один common reference для пары с фиксированными boundary node sets и profile; результат хранит конкретные origin/destination nodes. Сравнение разных выбранных пар узлов помечается как city-pair best-node analysis, не как один маршрут между одинаковыми платформами.

## Порог τ и вычислительная нагрузка
Базовая неделя — ближайшая предшествующая полностью покрытая обычная неделя без праздников, не более 8 недель назад; при отсутствии τ unknown. 28 срезов, направленные пары; точный пакетный расчёт в фоне без LLM. Результат кешируется по city, mode, graph, calendar, traffic_mode, population_version.
На первом анализе индекс с H доступен до готовности τ; метрика числа доступных объектов имеет отдельный pending job. Нельзя подменять τ фиксированными 15/30 минутами или выдавать случайную выборку за точный расчёт.
Для static дорожного режима отдельный static τ; расписания ОТ учитывают дату. Typical τ существует только при принятом typical profile. Сценарий не меняет базовый τ.

## Очередь, хранение, отказоустойчивость
Первая версия: PostgreSQL + PostGIS, одна jobs-таблица, worker берёт задания через FOR UPDATE SKIP LOCKED, lease/heartbeat и ограничение повторов. Redis/Celery не обязательны.
Immutable analysis_run: нормализованный запрос, snapshot/version/config hash, статус, время, результат/причина. Результат публикуется атомарно; повтор Idempotency-Key с другим payload →409.
UI опрашивает job; смена ползунка не запускает полный анализ до кнопки. Отмена кооперативная; потеря worker не означает вечный running.
Кеш traffic live имеет короткую годность по источнику; остальные результаты привязаны к snapshot, не к «текущим» данным.
OTP/Valhalla разворачивать как optional сервисы только после выбора конкретных стабильных image digests и сборки пробного графа. R5 не второй обязательный движок: его оконные median travel times не равны exact departure.
Размер графа/матриц измеряется на пилоте; национальный дорожный граф отдельный deployment, не требование к ноутбуку каждого участника.

Начать с Новороссийска/Калининграда по фактически принятому комплекту данных, не обещать готовность по размеру города. Все четыре контракта готовы одновременно; реализация по срезам не убирает ни один блок из ТЗ.
Текущие frontend fixtures и дизайн не переписываются; mockGateway заменяется адаптером API после публикации DTO. Готовые независимые PR в dev, ветки сохраняются.
