# Приёмка окружения и продукта

## Текущий этап

- Каждый пустой Python-проект имеет manifest и входит в один workspace. `uv lock --check`, frozen-установка всех members и `uv pip check` проверяют lock и зависимости. Базовая установка исключает тяжёлые группы. `notebooks` и `ml` можно подключить отдельно или совместно.
- В `apps/web/` проверяются `npm ci` и дерево прямых зависимостей. Включён strict TypeScript для будущих исходников. Конфигурации Vite, ESLint, Vitest и Playwright добавляет FRONTEND вместе с рабочими точками входа.
- `docker compose --env-file .env.example config --quiet` проверяет единственный сервис PostgreSQL 17. CI проверяет окружение без запуска приложения. Smoke-проверку подключения к БД выполняет DEVOPS после доступа к Docker Engine.
- Build SPA, typecheck, импорт будущих пакетов, запуск API, pytest и A2-evals ожидают реализации. Их результаты не являются частью готовности окружения.

Локально на macOS arm64 прошли проверка `uv.lock`, frozen-установка базового набора и групп `notebooks` и `ml` (отдельно и вместе), `uv pip check`, `npm ci`, `npm ls --depth=0` и проверка Compose. В обоих lock-файлах стабильные версии. `npm audit --omit=dev` не выявил уязвимостей. Полный аудит показал 10 записей moderate в инструментах разработки из одной зависимости `minimatch`. Docker Engine был недоступен. Проверка GitHub Actions на runner ожидает публикации. [Бюллетень minimatch](https://github.com/advisories/GHSA-g3hv-75wg-m249).

DEVOPS проводит проверку запуска и повторного подключения к PostgreSQL 17 в отдельном Compose-проекте. FRONTEND разбирает записи npm audit по `minimatch`, проверяет совместимость исправления и при необходимости обновляет npm manifest и lock.

## Будущие проверки поведения

| Область | Проверка и ожидаемое свойство |
| --- | --- |
| Данные | Отдельно принять и исключить один service date, проверить ночное событие предыдущего дня, неизвестную дату окончания, отсутствующую остановку и конфликт ключей. Пересборка тех же входов сохраняет версию и доказательства покрытия. |
| Маршрут | Учесть подход и выход, пропущенную пересадку, разные платформы, ночной рейс, `24:00+`, исключение календаря и поездку тем же рейсом без искусственной пересадки. На границе 48 часов путь допустим, если завершён вовремя. Проверить минимум 10 реальных маршрутов вручную. |
| Индекс | H=60 и длительность 60 минут дают вклад 0,5. Неизвестная ячейка остаётся в знаменателе с интервалом. Проверить отличие доказанного отсутствия и неполноты, границы 0–100, вклад известного пути при неполном графе, монотонность при добавлении альтернативы и повторяемость. |
| Сценарий | Сравнить две модификации на одинаковой версии базы и профиля. Проверить, что база неизменна, есть улучшения и ухудшения, а интервал, включающий ноль, не выдаётся за гарантированный выигрыш. Комбинации пересчитываются совместно. |
| API и SPA | Применение миграций к пустой БД, согласование JSON со схемой, отсутствие блокировки event loop при расчёте. На экране отображаются версии, источники, покрытие, ошибки и сравнение до/после. Позднее Playwright проходит сценарий сравнения и открывает пояснение маршрута. |
| Ассистент | Строгие схемы, отклонение неподдерживаемого инструмента, уточнение до вызова расчёта, явное сообщение о неполноте и недоступности. Каждый факт связан с фактическим ответом инструмента. Зафиксировать ошибки и независимую проверку результата ИИ. |

## Что требуется к сдаче

- U5 требует цель, чьи поездки и выбранные территории, гипотезу хорошей связности, единое правило и смысл показателей, рабочий инструмент с входом и выходом, сравнение территорий и пересчёт нескольких транспортных изменений. Также нужны пользователь, решения, ограничения, возможность переноса, путь от источника к выводу и проверка использованного результата ИИ.
- U2 задаёт паспорт 1–2 страницы и первый результат, презентацию 5–8 слайдов, выступление до пяти минут и план развития. Матрица относит к U2 срок 10 ноября 2026, 23:59. Часовой пояс в материалах не указан, московский часовой пояс в исследовании — рабочее допущение команды. Шаблон паспорта и форма загрузки, которые обещаны на слайде 7, в локальных материалах отсутствуют.
- P1, формула, шесть городов, выбор архитектуры и две конкретные модификации — решения команды. Гипотеза H0, эффект изменений, качество модели и переносимость требуют практической проверки. Источники требований и их трактовка собраны в [матрице](reference/Матрица_требований.csv).
