# Владельцы и передача изменений

| Роль | Сессия | Пути и ответственность |
| --- | --- | --- |
| FRONTEND | Codex | `apps/web/**`, `docs/tasks/frontend.md`. SPA, карта, клиентские типы и проверки, `package.json` и `package-lock.json`. |
| DEVOPS | Codex | `infra/**`, `.github/**`, файлы корня, `artifacts/**`, общие `docs/**` с исключением ниже. Все `pyproject.toml` и единственный `uv.lock`. |
| BACKEND | Codex | `apps/api/**`, `packages/contracts/**`, `contracts/generated/**`, `docs/tasks/backend.md`. HTTP, БД, миграции, канонические контракты и экспорт схем. |
| ML1 | Codex | `packages/engine/**`, `docs/tasks/ml1.md`. Детерминированная маршрутизация, индекс, сценарии и профиль расчёта. |
| ML2 | Claude Code | `packages/data_pipeline/**`, `packages/assistant/**`, `data/**`, `ml/**`, `docs/tasks/ml2.md`. Источники, snapshots, инструменты LLM и evals. |

Правила разрешения пересечений

1. Любой `pyproject.toml` и корневой `uv.lock` принадлежат DEVOPS, включая файлы внутри чужого модуля. Установка нового npm-пакета и изменение npm lock принадлежат FRONTEND.
2. Каждый `docs/tasks/<role>.md` принадлежит этой роли, включая `docs/tasks/devops.md`. Локальная документация принадлежит владельцу модуля. Общая архитектура и справочные материалы принадлежат DEVOPS с согласованием предметного содержания. BACKEND утверждает общие схемы, ML1 согласует семантику транспорта, ML2 согласует данные и ответы ассистента.
3. Роль работает в своей ветке и своём worktree либо отдельном клоне. Для БД использует отдельный Compose-проект с уникальным портом или изолированную тестовую БД/схему. Изменения общих схем и lock-файлов интегрирует владелец.

В handoff укажите путь, причину, необходимые поля или поведение, критерий приёмки и ссылку на коммит или результат проверки. Например, ML1 передаёт BACKEND запрос на `RouteResult.coverage_gap_ids`, объясняет область покрытия и перечисляет три статуса, для которых поле проверяется. Сообщение передаётся через участника команды или в согласованном месте репозитория.
