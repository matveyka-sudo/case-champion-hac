# ToolCall и ответ агента

BACKEND владеет одним продуктовым агентом, проверяемыми tools, журналом и evals. ML1 считает, ML2 поставляет принятую сеть, цели и evidence. FRONTEND показывает структурированные значения, пояснение и ссылки. См. ТЗ 1.1, с. 11, 13 и 17.

| Tool | Назначение |
| --- | --- |
| `get_coverage` | Подтверждённая область, дата и пробелы bundle. |
| `resolve_place` | Поиск места и явное уточнение неоднозначности. |
| `find_journeys` | Общий JourneyRequest с окнами и активными условиями. |
| `get_analysis` | Получить сохранённый run или job. |
| `evaluate_scenario` | Проверить ScenarioRequest и запросить пересчёт. |
| `get_evidence` | Получить зарегистрированную запись и источник по ID. |

Валидаторы REST/tools проверяют строгую схему, allowlist, диапазоны, ID, accepted bundle, версии, идемпотентность и бюджеты. Evidence обрабатывается как данные. В tools отсутствуют SQL, shell, произвольные URL-загрузки и исполнение кода. API-ключ остаётся на backend. Параметры R на вопрос — максимум 6 tool calls, 2 сценарных запуска, 4000 выходных токенов, 90 с интерактивного бюджета и до одного retry внутри того же бюджета. Сценарные операции ограничены отдельно. Долгая работа возвращает job. Модель и денежный лимит открыты в D4.

Ответ включает `summary`, `run_ids`, `evidence_ids`, `assumptions`, `limitations`, `scenario_operations`, `effects_by_profile`, `worsened_cases`, `feasibility_status` и `status`. Числа, условия и статусы сверяются с фактическим run и его версиями. Показ времени наследует зону запроса и именованные минуты/секунды домена. При недостаточных данных или отсутствии расчёта статус `insufficient_data`, обязательны `missing_fields` и причина, числовая рекомендация отсутствует. Недоступная LLM оставляет работоспособными формы и сохранённые runs. Резерв не закрывает F07.

`ToolCall` фиксирует `trace_id`, `call_id`, tool и его версию, model/prompt version, безопасные параметры, ссылки на job/run и bundle/profile/task/code versions, дату UTC, `latency_ms`, исход и ошибку, токены и стоимость с валютой, если они доступны. ID результата может быть null при отказе или уточнении. Причины инструмента используют общие ошибки и привязку к trace. Демо-логи хранятся 7 дней по умолчанию. Секреты, диагнозы, ФИО и необязательный свободный текст в журнал не записываются.
