# A2: формулы, общие правила и причины решений

Версия `a2-methodology-v3`, 08.11.2026. Согласованные формулы сохранены.
Финальное инженерное правило калибровки эталона A задано в разделе 6 и
IMPLEMENTATION.md. Методика утверждена для реализации; наличие всех исходных
данных проверяется отдельно. Параметры: config/product.json. Старые runs
хранят свою версию. Модель объяснения — Alice AI LLM Flash.

## 1. Полное время городской поездки

\[
T = T_{walk} + W_{initial} + T_{ride} + W_{transfer}.
\]

**Что значит.** Пешие участки, первоначальное ожидание, движение и ожидания всех
пересадок складываются один раз. Пеший переход между остановками входит в пешее
время, а не повторно в ожидание. Для автомобиля используется дорожное время
применимого режима; парковка не получает выдуманной постоянной надбавки.

**Почему так.** Ближайший объект по расстоянию может быть дальше по времени.
Сравниваются допустимые цепочки с одинаковым временем начала. Режимы пешком,
общественный транспорт с пешими участками и автомобиль выводятся раздельно.
В режиме общественного транспорта чисто пеший вариант тоже допустим.

**Пример.** 5 мин пешком + 7 ожидания + 15 в автобусе + 5 пешком = 32 мин.
Полное время определяет ближайший объект; линия и составляющие сохраняются.

## 2. Городской индекс категории

\[
I_{p,c,m}=100\cdot2^{-T_{p,c,m}/H_g}.
\]

**Что значит.** `p` — точка, `c` — категория, `m` — режим, `g` — город.
`T` — минимальное полное время до подходящего объекта. `H` и `T` в одинаковых
единицах. Отрицательна степень, а не время: при увеличении времени индекс
должен снижаться. При `T=0` индекс 100, при `T=H` — 50, при `T=2H` — 25.

**Почему так.** Непрерывное снижение без резкого обнуления за порогом.
`H` нормирует масштаб города, не сложность конкретной категории.

| Административная площадь города, км² | H, мин |
| --- | ---: |
| До 100 включительно | 20 |
| Более 100, до 300 включительно | 30 |
| Более 300, до 1000 включительно | 40 |
| Более 1000 | 60 |

Один H для всех категорий и режимов данного города. Площадь и граница должны
относиться к одной версии территории. Источник, дата, единицы обязательны.
При неизвестной площади H не угадывается. Заселённая площадь не подменяет
административную без новой версии методики. Это согласованные классы, не
оценённая по наблюдениям транспортная норма.

Низкая доступность: **I < 50**, эквивалентно `T > H`. Ровно 50 не относится к
низкой доступности. Отсутствие маршрута, доказанное на полном покрытии и в
заданном окне, даёт 0; неизвестные расписание/объекты/время дают `null`.

## 3. Общий индекс точки и территории

\[
I_{p,m}=\frac{\sum_{c\in C} w_c I_{p,c,m}}{\sum_{c\in C}w_c},
\qquad w_{low}=1,\quad w_{medium}=2,\quad w_{high}=3.
\]

**Что значит.** `C` — выбранные пользователем категории. Приоритет меняет их
вклад; выключенная категория не участвует. Отсутствие данных по выбранной
категории блокирует полный индекс точки, а не повышает его через исключение.

**Почему так.** Прозрачный приоритет без произвольных вводимых коэффициентов.
Пример: категории с индексами 100 и 0 и весами 1 и 3 дают 25.

\[
I_{R,m}=\frac{\sum_{p\in R}P_p I_{p,m}}{\sum_{p\in R}P_p}.
\]

**Что значит.** `P_p` — оценка числа жителей исходной представительной ячейки,
а не число людей внутри здания, куда перемещена точка. Точка в ТЦ не означает
население ТЦ и не получает число посетителей. Нежилую ячейку с нулевым
населением можно показывать на карте, но она не влияет на среднее жителей.
Если население неизвестно, оно не заменяется единицей или нулём.

**Почему так.** Доступность оценивается для жителей. При разбиении ячейки
границами районов доли населения суммарно не превосходят исходное население.
Каждый масштаб считается из исходных точек/долей; простое среднее районов
некорректно. При неизвестном индексе точки с положительным весом полный
территориальный индекс отсутствует. Частичный результат явно отделяется.

\[
Gap=\max_r I_r-\min_r I_r,\qquad Deficit_r=\max(0,I_{city}-I_r).
\]

**Что значит и почему.** Первый показатель — разрыв районов, второй —
отставание района от городского значения. Используются только сопоставимые
конфигурации; неизвестные районы не превращаются в нулевые.

## 4. Порог времени для числа доступных объектов

\[
\tau_{g,m}=\frac1{|S|}\sum_{s\in S}
\frac{\sum_{i\ne j,\,reachable}P_iP_j T_{ijm}(s)}
{\sum_{i\ne j,\,reachable}P_iP_j}.
\]

**Что значит.** Базовая обычная неделя без праздников, семь дней, моменты
08:00, 12:00, 18:00, 22:00: 28 равновесных срезов. Для каждого среза считается
взвешенное среднее времени между разными точками города; пары направлены.
Неизвестные пары сначала требуют проверки полноты; они не считаются
недостижимыми. Если у среза нет положительного знаменателя, τ неизвестен.

**Почему так.** Число доступных объектов получает порог относительно
типичного перемещения по городу и режиму. Это дополнительная метрика,
**τ не заменяет H** и не меняет формулу индекса.

\[
N_{p,c,m}=\#\{o\in c:T_{p,o,m}\le\tau_{g,m}\}.
\]

Дедуплицировать учреждения по идентичности, не по числу входов. Для оценки
недостижимых пар отдельно выводить их долю веса `P_i P_j`. После расчёта
базовой недели τ фиксируется для ползунка времени и сценариев. Если типичный
трафик не подтверждён, не выдавать расчёт без пробок за такой базовый профиль.

## 5. Ожидание, календарь и последний обратный рейс

\[
W_{initial}+\sum_k W_{transfer,k}\le4\text{ часа}.
\]

**Что значит и почему.** Городской предел применяется ко всему ожиданию в
цепочке, включая первое отправление. Это не предел длительности поездки и
не отдельные четыре часа на каждую пересадку. Время движения не добавляется
в этот лимит. 2 ч + 1 ч + 1 ч допустимы, ещё одна минута — нет.

Последний подходящий обратный рейс: найти последнее допустимое начало
возвращения от выбранного ближайшего объекта к исходной точке с посадкой
в выбранный календарный день. Прибытие после полуночи разрешено. Выводить
время выхода, первого отправления и прибытия. Чисто пешее возвращение —
`not_applicable`; часы работы и длительность визита не моделируются.

Календарь перевозчика и исключения приоритетнее общего производственного
календаря. Праздничный понедельник не автоматически равен воскресному
расписанию. Сезон влияет через подтверждённые расписания/профили, без
выдуманного зимнего множителя. Внутри engine — aware timestamps и UTC для
разностей, на экране — местное время территории.

## 6. Межгородской эталон A

\[
T^{ref}_{AB}=\min_{r\in R^{feasible}_{AB}}
\left(\sum_{e\in r}\frac{L_e}{v^{ref}_e}+T^{necessary}_r\right).
\]

**Что значит.** Расчётный эталон на существующей подтверждённой инфраструктуре.
Разрешены прямые и смешанные пути. `R` учитывает реальную связность, направление,
совместимость и допустимость пересадок; `L` — длина участка; `v_ref` — отдельно
зафиксированная эталонная скорость; `T_necessary` — неизбежные операции.
Используется общий эталон пары в сопоставимой области допустимых способов,
а не независимый «идеальный» эталон каждого вида транспорта.

**Почему так.** Можно оценивать эффективность, не требуя полного архива
лучших рейсов. Горы и извилистость учитываются существующей геометрией и
подтверждёнными атрибутами. Произвольного коэффициента труднодоступности нет.
Эталон не создаёт новые дороги, станции, паромы или грузовые услуги.

**Решение для реализации v3.** Эталонные затраты дороги — static/free-flow
cost закреплённой версии Valhalla и её costing profile. Для rail/air/water
используется минимальное подтверждённое время движения отдельного ребра в
принятом snapshot: v_ref = L / t_edge. Поиск по этим рёбрам допускает смешанные
пути. Это калибровка сети, не исторический минимум целой поездки между городами.
Неизбежные операции берутся из подтверждённых минимумов пересадок/обработки.
Нет исходного времени или операции — unknown/partial reference, а не нулевая
операция или выдуманная скорость. Полного рейтинга на partial reference нет.
Это новое инженерное уточнение; численные формулы индексов не изменены.
Эталон не отделяет естественную труднодоступность от недостатков сети.
Подробные границы времени и обработка неполноты — IMPLEMENTATION.md.

## 7. Пассажирский межгород

\[
I_{path}=100\min(1,T^{ref}/T_{path}),\qquad
I_{wait}=100\cdot2^{-W_0/(12\text{ часов})},\qquad
I_r=\sqrt{I_{path}\,I_{wait}}.
\]

**Что значит.** `W0` — ожидание первого отправления от выбранного момента.
`T_path` — время от первого отправления до прибытия, включая промежуточные
ожидания, переезды и операции. Первое ожидание не включается в `T_path`
повторно. Поиск отправлений — следующие 7 дней. Для одной цепочки берутся
оба компонента; нельзя соединять лучшее ожидание одного рейса с лучшим
временем другого. Время эталона относится к тем же границам пути.

**Почему так.** Раздельно учитываются эффективность пути и возможность
скоро уехать. Геометрическое среднее снижает оценку при слабом компоненте.
Пример: путь вдвое дольше эталона и ожидание 12 ч дают 50 и 50, итог 50.

По виду транспорта выбирается лучшая оценка подтверждённой цепочки;
общий пассажирский индекс — максимум среди общественных, включая смешанные.
Автомобиль отдельный, без ожидания отправления: только `I_path`.
При неполном наборе режимов результат предварительный, не полный рейтинг.

Частота — число уникальных фактических отправлений за явно указанный период
(кодшеринг не удваивает рейс). Количество видов транспорта, пересадок,
доля ожиданий в полном времени — расшифровки, не повторный штраф в индексе.
Город → город и субъект → субъект считаются отдельно; для субъектов в
пассажирском анализе используются столицы. Начало и конец — транспортные
узлы, не жильё. Необходимая смена узлов внутри цепочки входит во время.

## 8. Городская грузовая доступность

\[
I_{e,h}=100\cdot2^{-T_{e,h}/H_g},\qquad
I_{R,h}=\frac1{|E_R|}\sum_{e\in E_R}I_{e,h}.
\]

**Что значит.** `e` — физическая производственная площадка/склад,
`h` — тип подходящего грузового узла. Время до ближайшего по времени
совместимого узла; направления приёма и отправки раздельны. H такой же
городской по площади. Без достоверных объёмов площадки равновесны.

**Почему так.** Оценивается доступ предприятий к инфраструктуре. Веса
населения и фиктивные тонны сюда не подходят. Порт, станция, терминал
имеют отдельные оценки; предприятие не обязано пользоваться всеми видами.
Совместимость груза и допустимость грузового подъезда требуют данных.

## 9. Межгородские грузы

\[
T_{delivery}=W_0+T_{move}+T_{handling}+W_{transfer},\qquad
I_{cargo}=100\cdot2^{-T_{delivery}/D}.
\]

| Сценарий | D |
| --- | ---: |
| Срочный | 24 часа |
| Обычный | 72 часа |
| Несрочный на большие расстояния | 31 день = 744 часа |

**Что значит.** Полная доставка, каждый интервал посчитан однажды. Тип
продуктовый/непродуктовый, срочность, температурный режим и обработка —
разные признаки. Продуктовый груз не автоматически срочный.

**Почему так.** Срок задаёт чувствительность оценки; при T=D индекс 50.
Это не жёсткая отсечка: при T=2D индекс 25. Окно поиска отправлений —
31 день для всех трёх сценариев; доставка может завершиться позже.
Лучший совместимый вариант по каждому режиму, общий — лучший из них;
разные профили груза не усредняются. Показатель эффективности движения
по эталону можно выводить отдельно, без повторного штрафа.

Дорога или грузовая станция на карте не подтверждает перевозку и её
ожидание. При неизвестных операциях полного времени и индекса нет;
известное дорожное время можно показать отдельной исходной метрикой.

## 10. Трубопроводы

\[
U=100\cdot V/Q.
\]

**Что значит.** Загрузка подтверждённого участка/направления, где объём V
и мощность Q относятся к одному продукту, периоду и единицам. Q>0.
Нефть, нефтепродукты и газ отдельно. Системная мощность не равна мощности
пары территорий; линия через регион не означает подключения.

**Почему так.** Показатель инфраструктуры, а не индекс пассажирской поездки
или срочной доставки. В общий грузовой индекс не включается. `Q−V` не
выдаётся за коммерчески доступную мощность. Более 100% не обрезать:
нужна проверка сопоставимости данных. Неизвестное остаётся неизвестным.

## 11. Эффект сценария и потребность

\[
\Delta I=I_{after}-I_{before},\qquad
\Delta T=T_{before}-T_{after}.
\]

**Что значит и почему.** Положительные значения — улучшение; ухудшения
тоже выводятся. На одних точках, населении, H, τ, календаре, версиях графа
и трафика меняется только предложенная операция. Для появившегося пути
писать «связь появилась», а не бесконечную экономию минут.

Число затронутых жителей — сумма без дублей по ячейкам, где эффект доказан.
Для грузов — число площадок. Это потребность/охват, а не измеренный поток.
Согласование пересадки разрешено; добавление рейса требует обоснования
потребности и доступности ресурса. Численный пересчёт запускает только
«Проверить сценарий». LLM предлагает допустимую операцию и объясняет run.

## 12. Общие правила результата

- Единицы engine: секунды, метры; явное преобразование конфигурационных часов/минут.
- `available` — подтверждённое число; `unknown` — недостаточно данных;
  `methodology_pending` — не определены параметры метода;
  `not_applicable` — метрика неприменима. Это разные состояния.
- Неизвестный объект/рейс не является доказанным отсутствием. HTTP-ошибка не даёт 0.
- Один знак после запятой на экране; расчёты и сортировка без промежуточного округления.
- Рейтинг только сопоставимых конфигураций, режимов, дат/периодов и версий.
- Стоимость, такси, каршеринг, достопримечательности и индекс актуальности исключены.
  Техническое происхождение, период и ограничения данных сохраняются.
- Географию, расписания и скорости хранить структурированно. В RAG — методики,
  определения, документы и пояснения; LLM не заменяет маршрутизатор.

## Граничные условия вычислений v3
Все длительности конечны и неотрицательны, H и D строго положительны. Для
отношения эталона T_path должен быть >0; нулевой межгородской путь для разных
территорий — INVALID_PATH_TIME, а не деление на ноль. Отрицательное ожидание
означает невалидную временную цепочку. Нулевая сумма весов/населения даёт
not_applicable, не нулевой индекс. Нет выбранных категорий — ошибка запроса.
Окна поиска отправлений полуоткрытые [start, start + 7/31 суток). Конец окна
не ограничивает прибытие. Поиск не ограничивается прямыми путями; если API
дал только часть цепочек, статус полного межгородского результата partial.
Доля ожидания = (W_initial + sum W_transfer) / T_total при T_total >0;
иначе not_applicable. Это расшифровка, не дополнительный штраф.
