## Найденные блокеры и изменения

Исходный аудит установил критический путь: штатная установка ML2/ML1 → проверенный AcceptedData и подходы → граф из соответствующего PBF → реальный locate/route с явной точностью → calculation adapter → отдельный worker и PostgreSQL → существующий API-режим UI. Очередь, транзакционная публикация, DTO и браузерный polling уже существовали; заменять их не потребовалось. Полный городской рейтинг заблокирован полнотой данных и доказательством минимума; ограниченный реальный пилот проходит этот путь без изменения формул.

1. ML2 был виртуальным workspace-пакетом, поэтому обычная установка не давала импорт `a2_data_pipeline`. `312d648`: добавлена штатная сборка и зависимости API на ML2/engine; lock обновлён без обновления сторонних версий.
2. `9ece5b5`: исправлен устаревший путь ProductRegistry в README, устранён воспроизводимый сбой исходного CI.
3. `b62e0cd`: ML1 теперь явно представляет шестизначную сериализацию привязки с доказательством её происхождения. Половина единицы последнего знака — предел совместимости; более крупный сдвиг отклоняется. При такой неопределённости минимум и глобальное отсутствие пути не подтверждаются.
4. `a8df5ac`: узкий реальный walk-adapter, registry/preflight, проверка immutable artifact, ограниченный HTTP executor и canonical DTO bridge. Сохранены существующие cancel/timeout/lease/heartbeat/fenced publication и права сессии.
5. `fb993e2`: сохранены источники населения ячейки и обоих подходов в выводимых доказательствах.
6. `134b5d8`: маркеры `py.typed` для штатно установленных ML1/ML2; независимая проверка обнаружила проблему, которую маскировал source PYTHONPATH исполнителя.
7. `c0e93f2`: отдельная CI-проверка ML2 с установленными workspace-пакетами.
8. `8ef8d9b`: воспроизводимые pinned build/selection/artifact/verification и launcher в `infra/real-e2e/`. Проверены на новой сборке.
9. `0e9eb1b`, `84c7318`: русские подписи трёх метрик и десяти ограничений, отдельный живой браузерный тест с JSON и desktop/mobile screenshots.
10. `1824db8`: новая ML2 CI обнаружила расхождение Linux/macOS при классификации водной ячейки. Узкая поправка fixed-precision overlay в пределах восьми ULP влияет только на причину исключения; исходная геометрия, площадь и размещение точек сохраняются. Четыре регрессии отличают численный остаток от настоящей полосы суши 1 мкм, острова 1 мм и ячейки без воды. Координатор повторил 221 тест; [Linux CI исполнителя](https://github.com/matveyka-sudo/case-champion-hac/actions/runs/42806846717) прошёл. Принятые bundles не пересоздавались.

Поставки прошли RUNNING → REVIEW → ACCEPTED → INTEGRATED после проверки координатором. На review исправлены неполные ссылки на evidence, отсутствие py.typed и проверка всех кандидатов locate. Исходные snapshot, формулы и wire-контракты сохранены.

## Измерения и ограничения

Сборка графа: 8,95 с. Первый UI-job: 0,620935 с от создания до завершения, из них worker — 0,506560 с. Это один маленький пилот, не SLA полного города. Разовый Docker memory sample: Valhalla 78,5 MiB, PostgreSQL пилота 180 MiB; пик памяти не измерялся.

Остаются частичный каталог школ, неполное население, одна выбранная точка/школа, отсутствие доказанного глобального минимума и τ. Геометрия сети сохранена в routing evidence, но не выдаётся за полную геометрию физического пути с подходами; UI получает реальные точки и честное ограничение геометрии. Для полного города нужны подтверждённые привязки и маршруты всех требуемых пар, полнота весов/категорий, доказательство минимума либо отдельный согласованный вид показателя и измерение нагрузки.
