## Что реально работает и что ещё не завершено

| Направление | Текущая граница |
| --- | --- |
| Москва, Калининград, Новороссийск | Городские пешие профили по принятым данным; реальные маршруты, карта, сохранение результата |
| Индексы | Есть частичные численные оценки найденных маршрутов; строгий минимум, полные категорийные/городские индексы не доказаны |
| Группы категорий | Backend принимает один запрос, worker последовательно считает категории, сохраняет отдельные результаты, поддерживает отмену и повтор; кнопка группового запуска в React ещё не подключена |
| Городские грузы | Worker рассчитывает маршруты Калининграда и Новороссийска; в Москве 2222 площадки, но нет принятых грузовых объектов назначения |
| Межгород | Четыре подготовленных автомобильных направления; произвольный новый межгородный маршрут и полноценные расписания ещё не подключены |
| Межгородские грузы, трубопроводы | Нет достаточных принятых данных для полной цепочки/сопоставимых объёмов и мощностей |
| Сценарии | Есть ограниченные работающие пути; полный набор сценариев для всех направлений не принят |
| Alice | Объясняет сохранённые результаты; чистый запуск не включает платную модель автоматически |

Отсутствие данных не превращается в ноль. Частичная оценка маршрута не означает
индекс всего города. При добавлении города используется общий pipeline, а не
новый engine/API для каждого города.

## Какие файлы передать отдельно от Git

У владельца подготовлена папка на рабочем столе:
`waydex-handoff-2026-11-11/`. Передайте её целиком согласованным файловым каналом.
Внешняя ссылка на скачивание пока не опубликована.

```text
waydex-handoff-2026-11-11/
  START-HERE.md             копия этой инструкции
  runtime.tar.gz            принятые snapshots, supplements, доказательства и профили
  graph-transfer.tar.gz     графы трёх городов и привязки
  release-pins.json         утверждённые версии и контрольные суммы
  SHA256SUMS                суммы транспортных файлов
  artifact-receipt.json     размеры и состав пакета
```

Архив `ml2-handoff-2026-11-10.zip` — исходная поставка ML2. **Одного этого ZIP
недостаточно для нынешнего стенда**: после него добавлены принятые supplements,
маршрутные графы, привязки и runtime manifest. Для запуска используйте пакет выше.
Исходный ZIP потребуется отдельно, если продолжаете ingestion/верификацию ML2.

## Чистый запуск

Нужны Git, Python **3.12**, Docker с Compose v2 и доступ к образам/пакетам при сборке.
Для редактирования нужны uv `>=0.12.17,<0.13` и Node; контейнер фронтенда использует
Node `24.22.2`. Желательно выделить Docker 8–12 GiB RAM и оставить примерно 20 GiB
свободного диска: это запас для графов, образов и сборки, не измеренный минимум.

Проверено на Docker/macOS ARM64 с Linux ARM64 приложением и указанным в Compose
PostgreSQL образом. Linux AMD64/Windows и удалённый сервер отдельно не приняты;
native certificate должен соответствовать архитектуре. Не подменяйте его checksum
для обхода проверки. Подробности: [PRODUCT_RESTORE](../infra/full-stack/PRODUCT_RESTORE.md).

Команды ниже выполняются в bash/zsh в новой рабочей папке. Переменную `artifacts`
поменяйте на абсолютный путь к полученной папке. Пути не должны содержать символы
интерполяции `.env`: `$`, `#`, кавычки или переводы строки.

```sh
mkdir -p waydex-team
cd waydex-team
workspace="$PWD"
artifacts="/absolute/path/to/waydex-handoff-2026-11-11"

git clone --branch integration/cargo-observations-20261111 \
  https://github.com/matveyka-sudo/case-champion-hac.git source
source="$workspace/source"
git -C "$source" switch --detach 3d225a2c41776c045b8eefe53ef9e60796f41942

mkdir -p "$workspace/private" "$workspace/data"
private="$workspace/private"
runtime="$workspace/data/runtime"
transfer="$workspace/data/transfer"
pins="$artifacts/release-pins.json"
pins_sha=c080cef135e35b899d041fb6db9b2d990b4f320306a0d9def4a4e8ffdeb19b05
archive_sha=3e97ff74113bf40503d7f35082ac268a620175a0edf9349c52490d1d7737ef47
bundle_sha=518b6cf31b799286a8bff364ad58d32cccb17bd96bc825d68f934c28ba836ee3
```

Проверьте транспортные файлы до распаковки. В macOS:

```sh
(cd "$artifacts" && shasum -a 256 -c SHA256SUMS)
```

В Linux можно использовать `(cd "$artifacts" && sha256sum -c SHA256SUMS)`.
Далее общие команды. При несовпадении суммы остановитесь и получите правильный
файл; не переписывайте ожидаемую сумму.

```sh
tar -xzf "$artifacts/graph-transfer.tar.gz" -C "$workspace/data"
python3.12 "$source/infra/full-stack/bundle.py" restore \
  --archive "$artifacts/runtime.tar.gz" --sha256 "$archive_sha" \
  --manifest-sha256 "$bundle_sha" --output "$runtime"
python3.12 "$source/infra/full-stack/four_profile_restore.py" verify \
  --runtime "$runtime" --transfer "$transfer" \
  --release-pins "$pins" --release-pins-sha256 "$pins_sha"

revision=$(git -C "$source" rev-parse HEAD)
docker build -f "$source/infra/full-stack/api.Dockerfile" \
  -t "waydex-full-api:$revision" "$source"
docker build -f "$source/infra/full-stack/web.Dockerfile" \
  -t "waydex-full-web:$revision" "$source"
executor_sha=$(docker run --rm --network none \
  --entrypoint /app/.venv/bin/python "waydex-full-api:$revision" \
  -c 'from a2_api.adapters.walk_runtime import executor_fingerprint; print(executor_fingerprint())')

python3.12 "$source/infra/full-stack/product_env.py" \
  --source "$source" --revision "$revision" --executor-sha256 "$executor_sha" \
  --runtime "$runtime" --transfer "$transfer" \
  --release-pins "$pins" --release-pins-sha256 "$pins_sha" \
  --project waydex-team-v1 --port 5294 --output "$private/product.env"

"$source/infra/full-stack/product-compose.sh" \
  --env-file "$private/product.env" up -d --no-build --wait
```

Откройте **http://127.0.0.1:5294/#atlas**. Compose запускает PostgreSQL/PostGIS,
проверку данных, три Valhalla, Alembic, API, worker и React/nginx. Существующая
Kaliningrad-сессия или сеть другого проекта не нужны. Генератор `.env` создаёт
пароль БД и сам находит пути в восстановленной структуре. Архивы остаются вне Git.

Генератор требует чистый checkout и не перезаписывает готовый `.env`. Сохраните
этот файл: повторное создание случайного пароля не меняет пароль уже существующей
БД. Для повторного запуска достаточно последней команды `up`; ничего распаковывать
или заранее рассчитывать заново не нужно.

## Быстрая проверка после запуска

```sh
curl --fail http://127.0.0.1:5294/health
"$source/infra/full-stack/product-compose.sh" --env-file "$private/product.env" ps
"$source/infra/full-stack/product-compose.sh" --env-file "$private/product.env" \
  logs --tail 80 api worker runtime-check migrate
```

В интерфейсе выберите Новороссийск → городской пассажирский → пешком → взрослые
поликлиники, дату **11.11.2026**, время **08:30**, static. Запустите расчёт и дождитесь
карты/сохранённого результата. Это исторический принятый срез: произвольная текущая
дата, транспорт или категория вне capabilities не становятся доступными сами.

Кнопка обычного анализа создаёт PostgreSQL job. Worker получает параметры,
разрешает snapshot, выполняет доступный расчёт и сохраняет результат. Совпадающий
допустимый запрос может использовать кеш. CLI `precompute` для обычных подключённых
городских walk/truck запросов не обязателен. Межгород пока использует подготовленные
автомобильные наблюдения — это отдельное незавершённое направление.

Для групп нового backend см. [analysis-groups](../apps/api/docs/analysis-groups.md):
`POST /api/v1/analysis-groups`, получение статуса, отмена и retry. Пока не подключён
React, не выдавайте этот API за готовую кнопку массового расчёта.

Остановка с сохранением результатов:

```sh
"$source/infra/full-stack/product-compose.sh" --env-file "$private/product.env" stop
```

Не применяйте `down -v` к стенду с нужными результатами. Для интернета дополнительно
нужны HTTPS reverse proxy и настройки secure cookies: текущий порт слушает loopback.

## Как продолжить править

Создавайте отдельную ветку от поставки, не коммитьте напрямую в `dev`:

```sh
git -C "$source" fetch origin
git -C "$source" switch -c feature/my-next-task origin/integration/cargo-observations-20261111
```

Сначала прочитайте `AGENTS.md`, `docs/OWNERSHIP.md` и локальные инструкции модуля.
Фронт — `apps/web`, оркестрация — `apps/api`, математика — `packages/engine`, данные —
`packages/data_pipeline`, контракт — `packages/contracts`. Не создавайте отдельные
ручки/engine для каждого города и не меняйте формулу ради заполнения dashboard.

Для фронтенда можно оставить Docker backend и включить Vite с API proxy:

```sh
cd "$source/apps/web"
npm ci
VITE_DATA_MODE=api BACKEND_PROXY_TARGET=http://127.0.0.1:5294 \
  npm run dev -- --host 127.0.0.1 --port 5173
```

Открывайте `http://127.0.0.1:5173/#atlas`. Demo — отдельный режим для дизайна, он не
доказывает расчёт backend. Существующий визуальный дизайн сохраняем.

Python workspace для разработки:

```sh
cd "$source"
uv sync --frozen --all-packages
export PYTHONPATH=.:apps/api/src:packages/contracts/src:packages/assistant/src:packages/engine/src:packages/data_pipeline/src
```

Проверяйте изменённую область, а не запускайте бесконечно весь suite. Например,
`uv run --frozen pytest apps/api/tests/test_analysis_groups.py -q`; эти тесты требуют
`A2_TEST_DATABASE_URL` отдельной тестовой PostgreSQL БД и без неё будут пропущены.
Фронт: `npm run typecheck`, `npm test`, `npm run build` в `apps/web` по необходимости.
После изменения DTO обновите экспорт `python -m a2_api.exports.schemas --output
contracts/generated` и `npm run api:generate`.

Контейнеры используют собранные образы, а не изменения файлов автоматически.
После backend-правок нужны коммит, новая сборка API/worker и согласованные
`WAYDEX_REVISION`/executor fingerprint. Сохраняйте пароль/volumes существующего стенда;
для независимого эксперимента проще новый project и новый private env. Старые группы
не продолжаются на другой версии кода: создайте новый запрос, сохранив старые результаты.

## Alice и оставшиеся задачи для нового плана

В чистом комплекте нет личных API-ключей и live opt-in. Аналитика работает без LLM;
смотрите [Alice integration](../apps/api/docs/alice-integration.md) для серверных
настроек, read-only tools и бюджета. Не переносите старый бюджет автоматически,
не кладите ключи в `VITE_*`. Лимит Яндекс Расписаний — 500 запросов в день; передачей
не разрешается массовый сбор или новая платная нагрузка.

Незавершённое на момент остановки: React-путь групп категорий; полный пользовательский
replay групп; строгие минимумы и численные индексы/районы; остальные принятые
городские транспортные профили; on-demand межгород и расписания; недостающие грузовые
и трубопроводные входы; расширение сценариев/Alice; удалённый запуск и независимый
review. Это список состояния, новый порядок работ определит владелец проекта.

Последняя серверная поставка: 54 проверенных теста затронутого пути (15 новых групп),
реальный запуск двух категорий Новороссийска — 606 маршрутов; каноническая валидация,
повторное чтение и изоляция сессий прошли. Детали и ограничения лежат в документах
модуля. Последний GitHub CI нужно смотреть по фактическому HEAD PR, а не переносить
статус старого коммита. Независимый reviewer упёрся в лимит аккаунта; review не завершён.
