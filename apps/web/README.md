# Waydex frontend

Активное приложение — `apps/web/`; структурный перенос выполнен в `fix-fullstack`, постоянная ветка FRONTEND — `work/frontend`. React + TypeScript strict + Vite. Утверждённый HTML-прототип перенесён в компоненты без iframe, вставки всей страницы через innerHTML и запуска монолитного скрипта прототипа.

## Запуск

```sh
cd apps/web # из корня репозитория
npm ci
npm run dev
```

Откройте адрес Vite. Для конкретного порта: `npm run dev -- --host 127.0.0.1 --port 5176 --strictPort`.

`#top`, `#about`, `#features`, `#how` — лендинг; `#atlas` — атлас. Back/forward работают. Макет адаптирован к 1440/1280/768/390 px. Если приложение открыто в локальной сети, используйте соответствующий host отдельно.

## Данные и ограничения

Есть два явных режима: **demo** (по умолчанию) и **api**. API-путь использует опубликованный контракт. Отдельно проверен реальный частичный пеший расчёт Калининграда до школы; остальные виды live-анализа и платная LLM этим не подтверждены. Ниже описаны только ограничения демо-данных. Данные взяты из утверждённого прототипа; provenance и SHA-256 HTML — `src/mocks/source.json`. Индексы заранее подготовлены, транспортная формула в браузере не рассчитывается. Взвешивание выбранных демо-категорий и отображение агрегатов — presentation selectors над fixtures, не утверждённая методика. В режиме `pending` индекс скрывается. Демонстрационный режим и его метки сохраняются отдельно от API.

Москва: сетка, объекты, 44-минутная цепочка и согласование пересадки. Калининград: частичные данные. Новороссийск: нет пассажирской сетки; грузовой пример есть. Пассажирская пара: Москва ↔ Калининград; грузовая — Москва ↔ Новороссийск. Другие справочные пары честно показывают отсутствие демо. Baseline на 10 ноября 2026, 08:30. Другие слоты не создают фиктивных результатов. 96 положений таймлайна, автоночь 20:00–05:45 — правило дизайна, не астрономия.

Google Fonts (Manrope/Unbounded) и городские тайлы OSM требуют сети. Natural Earth/world-atlas суша, фото и fixtures лежат локально. Есть attribution OSM и обработка недоступной подложки. Прототип не рассчитан на массовое использование публичного tile-сервера; production-поставщик выбирается отдельно. Фото предоставлены пользователем, права на публикацию не подтверждались. У недостающих фото сохранены оформленные заглушки из оригинала. Все библиотеки ставятся через npm, UMD/CDN-скриптов в приложении нет.

## Структура

- `src/pages/LandingPage.tsx`: точная композиция HTML; `features/motion.ts`: scroll/reveal и cleanup.
- `src/pages/AtlasPage.tsx`: композиция рабочего пространства и async-запросы.
- `src/features/state.ts`: типы, reducer, draft/applied условия, revision guard; `AtlasProvider.tsx`: провайдер.
- `src/widgets/`: React-фильтры, Leaflet CityMap, d3 RussiaMap, карточка, легенда/таймлайн, агент.
- `src/mocks/catalog.*`: лёгкие справочники для лендинга; `public/data/demo/` (manifest и небольшие части по городам): предрасчитанные детерминированные fixtures; `mocks/model.ts`: view models/selectors; `mocks/gateway.ts`: отменяемый async mock gateway.
- `src/shared/`: иконки, форматирование, цвет, время.
- `src/styles/prototype.css`: исходные токены, keyframes и адаптивность; `integration.css`: минимальные исправления интеграции React/Leaflet.

Карты меняют DOM только внутри своих ref. Listeners, observers, карты, animations/timers освобождаются. Свободный ввод чата выводится безопасно как текст; подготовленные ответы представлены React-структурой. Escape/Tab и возврат фокуса поддерживаются в мобильных панелях. Таймлайн/выбор условий не запускают расчёт автоматически; revision guard и AbortSignal защищают от поздних ответов. Проверка сценария — отдельное действие; база не перезаписывается.

## API-интеграция

Инструкция и передача владельцам — [общая API-интеграция](../../docs/FRONTEND_INTEGRATION.md). Использовать Node 24.22.2. Для API скопировать `.env.example` в `.env.local`, указать фактический `BACKEND_PROXY_TARGET`, оставить `VITE_DATA_MODE=api`. Production reverse proxy на том же origin настраивает DevOps. Для явного разового переключения: `/?data=api#atlas` или `/?data=demo#atlas`. API-ошибка никогда не включает демо автоматически.

Типы и runtime-валидация генерируются из `../../contracts/generated/openapi.json`: `npm run api:generate`; проверка актуальности — `npm run api:check`. URL prefix `/api/v1`, schema_version `2`. API-composition изолирована от fixture selectors, сохраняет стиль сайта и общие controls. Расчёты, рейтинги и эффекты сценариев в браузере не вычисляются.

Подготовлены session bootstrap, реальные каталоги, четыре запроса, IANA-время, jobs/cancel, map_data, сохранённые результаты, explanation и server scenarios. Обычные HTTP E2E используют синтетические канонические DTO и не подтверждают live-интеграцию. Отдельная opt-in проверка ниже подтверждает только принятый частичный пеший срез через реальные API, PostgreSQL, worker и engine. Формулы исполняются на сервере; платная LLM в эту проверку не входит.

## Проверки

```sh
npm run api:check
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E поднимает Vite на 5176 или использует уже работающий сервер. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` позволяет указать установленный Chromium. Проверки не зависят от публичных OSM-тайлов: используется тестовая заглушка. Скриншоты с реальными тайлами проверяются отдельно. Unit-тесты — reducer, stale responses, отмена mock job, контрольные fixtures. E2E — навигация, темы, время, сценарий, чат, все статусы, направления, грузовые режимы и mobile.

`PLAYWRIGHT_WEB_PORT` задаёт отдельный порт E2E для изолированного worktree; по умолчанию остаётся 5176. При `CI=1` Playwright запускает свой сервер вместо использования существующего.

В API городской список ограничен `urban_city_names` сервера; межгород сохраняет полный каталог. Когда сервер публикует `snapshots`, интерфейс проверяет область и дату отправления в часовых поясах обеих территорий. Единственный подходящий набор разрешается автоматически и показан с периодом и версией. При перекрытии периодов пользователь выбирает набор явно; запрос содержит его `snapshot_id`. Неизвестные границы периода не считаются неограниченным покрытием. При изменении территорий, даты или времени прежний выбор сбрасывается. Если сервер не публикует это необязательное поле, разрешение набора остаётся серверным. Детальное покрытие по режимам всё равно проверяет backend.

Трубопроводные профили показаны только для выбранного продукта. Частичный численный индекс сохраняет утверждённый цветовой диапазон и дополнительно обозначен точечным контуром, прозрачностью и подписью в tooltip. Нулевой индекс остаётся числом; неизвестный — серым. Последние обратные рейсы в карточке ограничены выбранной точкой или объектом назначения; ячейка связывается с точками через серверные поля.

Объяснения поддерживают ссылки `score_ids` и `score_claims` из канонического Finding наряду с прежними метриками. Значения, статус и полнота индекса берутся только из сохранённого `AnalysisResult.scores`; числа из текста или claims не подменяют результат. Численные индексы в карточке и объяснении используют диапазоны `<50`, `[50,75)`, `≥75`, а неизвестные остаются нейтральными. Общая подпись landing в API-режиме отделяет демонстрационные примеры страницы от результатов API в атласе.

В сценарном представлении пути выбираются по ссылкам `after.metrics[].journey_id` из объединённого каталога исходных `journeys` и дополнительных `after_journeys`. Поэтому явно переиспользованный исходный путь сохраняется, изменённый путь к любому объекту получает новые серверные время/цепочку/геометрию, а потерянный путь не подставляется из базы. Карточки показывают сведения о сценарных путях даже при `geometry: null`; карта в этом случае сообщает об отсутствии геометрии и не строит условную линию. Объекты карты остаются из исходного анализа. Переключение «База» восстанавливает исходные значения и маршруты; ухудшения и события появления/потери связи сохраняют серверный знак и статус.

`urban_passenger_scopes` уточняет доступные городские пассажирские запуски. `null` или отсутствие поля сохраняет legacy-поведение, `[]` явно означает отсутствие зарегистрированных параметров. Запуск требует ровно одного профиля, который одновременно покрывает город, snapshot, область запроса, способ передвижения, трафик, все категории и момент `[valid_from, valid_to)`. Составные категории разных профилей не объединяются; неоднозначное совпадение блокируется. `whole_city` разрешает запрос без района и не означает полноты городского индекса.

Недоступные варианты остаются видимыми с причиной. Уже выбранные неподдерживаемые категории можно снять; даты, время и передвижение не заменяются автоматически. Действие «Использовать доступные параметры» сначала показывает конкретный предлагаемый набор и применяет его только по нажатию. Допустимый запуск не обещает численного индекса: сохранённые `unknown` и `partial` продолжают отображаться отдельно.

В начале городской пассажирской карточки доступен явный обзор «Рассчитанные точки». Он включает только точки с однозначным общим численным индексом, включая ноль; отдельная категория не заменяет неизвестный общий индекс. Знаменатель берётся из уникальных `sample_point` переданной карты, а не из ячеек или количества score. При отсутствии согласованной выборки соотношение не выдумывается. Индекс города остаётся подписанным отдельно, в том числе при неизвестном значении.

Открытие обзора не меняет выбранную точку или параметры. Нажатие на точку открывает существующую карточку, явно подсвечивает и показывает её на карте при наличии координат. «Все показатели» возвращает полный ответ, включая неизвестные значения. Без человекочитаемого имени отображаются координаты серверной точки; технические ID не становятся названиями. Большой сценарий UI-тестов генерируется в памяти из синтетического fixture; реальный JSON анализа в репозиторий не включён.

Подробности визуальной проверки — `docs/VISUAL_QA.md`. Непроверенные реальные интеграции не считаются завершёнными.

## Границы приложения

`src/shared/` используется только Waydex. `public/` раздаётся от корня URL:
`/assets/`, `/data/`, `/icons.svg`. Перенос каталога на диске не меняет Vite base,
hash-маршруты, API prefix или публичные URL ресурсов.

Manifest и npm lock перенесены вместе без изменения зависимостей. Корневых npm
workspaces нет. Генератор `scripts/generate-api.mjs` обслуживает только web;
общий OpenAPI разрешается относительно файла скрипта. Из корня также работает:
`node apps/web/scripts/generate-api.mjs --check`. Shared CI/layout check находится
в корневом `scripts/check_web_layout.mjs`.

Сверка UI: [FRONTEND_UI_SCOPE_REVIEW](../../docs/FRONTEND_UI_SCOPE_REVIEW.md).
Исторический visual QA и фото остаются в локальном `docs/` приложения.

## Отдельная проверка реального пешего расчёта

`playwright.live.config.ts` запускается только с `WAYDEX_RUN_LIVE_E2E=1` и не
входит в обычный набор 21 браузерного теста с fixtures. Перед запуском нужны
работающие API, PostgreSQL, worker и Valhalla с принятым неизменяемым runtime
из [backend walk pilot](../api/docs/walk-pilot.md). Frontend должен проксировать
`/api/v1` на этот API. Тест не подменяет HTTP, cookies или результаты.

Из `apps/web`, с установленными Node 24 и Chromium:

```sh
WAYDEX_RUN_LIVE_E2E=1 ./node_modules/.bin/playwright test --config playwright.live.config.ts
```

Адрес по умолчанию — `http://127.0.0.1:5178`; для другого запущенного frontend
задайте `WAYDEX_LIVE_BASE_URL`. Каждый запуск создаёт новую браузерную сессию,
выбирает Калининград, пеший режим, только школы и принятую дату 10.11.2026,
отправляет настоящий запрос и читает сохранённый результат этой сессии.

Для текущего принятого образца проверяются 547,404 секунды полного пути,
частичный охват, неизвестный индекс и запрет рейтинга. Другой браузерный контекст
должен получить 404 при чтении результата. Полный hash не сравнивается между
запусками: identity и время получения evidence различаются. Чат, платная модель,
запуск сценариев и Яндекс Расписания в этой проверке не вызываются.

JSON запроса, job и сохранённого результата, а также desktop/mobile screenshots
сохраняются в игнорируемом `live-test-results/`. Эти файлы подтверждают только
реально выполненный запуск; наличие теста само по себе не доказывает live-приёмку.
