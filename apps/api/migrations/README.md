# Миграции PostgreSQL 17

Alembic использует SQLAlchemy и asyncpg только для миграций. Runtime работает через
параметризованный SQL asyncpg. Ревизия `0001_jobs_runs` создаёт таблицы `runs` и
`jobs`, внешний ключ результата, ограничения состояния job и индексы очереди/кэша.
Асинхронным миграциям требуется зависимость SQLAlchemy `greenlet` (extra
`sqlalchemy[asyncio]`); её подключение к manifests/lock согласуется с DEVOPS.

Из корня репозитория под подготовленным окружением:

```bash
# DATABASE_URL is read from the repository-root .env; DATABASE_SCHEMA defaults to a2_backend.
.venv/bin/alembic -c apps/api/alembic.ini upgrade head
.venv/bin/alembic -c apps/api/alembic.ini current
```

Не записывайте действительные учётные данные в Git или журналы. Допустимы также
URL `postgresql://` и `postgres://`: соединение миграций использует asyncpg.
Без `DATABASE_URL` миграция завершается ошибкой конфигурации. При запуске из
корня репозитория Alembic читает `.env`; переменные процесса имеют приоритет.
Старые имена `A2_DATABASE_URL` и `A2_DATABASE_SCHEMA` временно поддерживаются,
но конфликтующие значения отвергаются без вывода URL.

При программном запуске `Config.attributes['database_url']` и
`Config.attributes['database_schema']` имеют приоритет над переменными окружения.
Схема по умолчанию — `a2_backend`, допустимое имя соответствует
`^[a-z][a-z0-9_]{0,62}$`. Невалидное имя отвергается до подключения к БД.
Пользователь БД должен иметь право создавать целевую схему и её таблицы.

Целевая схема создаётся при отсутствии. Все таблицы, внешний ключ и
`alembic_version` привязаны к этой схеме; `search_path` действует локально внутри
транзакции миграции. `upgrade head` повторно не выполняет уже применённую ревизию.

`input_hash` описывает нормализованный запрос для идемпотентности. Уникальная пара
`(kind, idempotency_key)` сохраняет исходный job. `cache_key` дополнительно включает
версии контекста/кода; частичный индекс по нему охватывает только succeeded jobs.
Состав и вычисление хэшей принадлежат runtime, миграция хранит готовые значения.

Проверка на отдельной тестовой схеме: применить `upgrade head` к пустой схеме,
повторить upgrade, проверить ограничения/FK, выполнить downgrade и снова upgrade.
Для downgrade:

```bash
.venv/bin/alembic -c apps/api/alembic.ini downgrade base
```

Downgrade удаляет только `jobs` и `runs` из выбранной схемы. Сама схема,
`alembic_version` и чужие таблицы остаются. Поэтому эту команду нужно выполнять
только для явно выбранной тестовой схемы или при намеренном откате её данных.
Интеграционные проверки должны использовать уникальную `a2_test_<suffix>` схему.

Offline-вывод SQL для просмотра без подключения:

```bash
.venv/bin/alembic -c apps/api/alembic.ini upgrade head --sql
```

Проверки подключения и миграций требуют PostgreSQL. Offline-вывод не доказывает
применимость ревизии к реальной БД.
