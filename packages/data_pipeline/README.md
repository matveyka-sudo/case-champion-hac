# a2_data_pipeline (ML2, №5)

Реестр источников, загрузка raw с хэшами, QA и принятые bundle данных для engine и BACKEND.
Действующая постановка — `docs/PRODUCT_SPEC.md` 2026-11-08.1.

## Runtime inputs — 10.11.2026

`runtime_inputs` восстанавливает локальные внешние файлы из ML2 handoff без
сетевых запросов. Пины лежат в `data/manifests/external/runtime-handoff-2026-11-10.json`.
До записи проверяются все SHA256, происхождение и количество строк привязок.
Каждый файл/каталог публикуется атомарно с исключительным созданием; повторный
запуск использует совпадающие байты и отказывается заменять другие.
Привязки Расписаний остаются только в игнорируемом `data/processed/yandex_rasp/`;
публичный отчёт содержит количество строк и хэши.

```bash
export PYTHONPATH=packages/data_pipeline/src:packages/engine/src:packages/contracts/src
python -m a2_data_pipeline.runtime_inputs --restore-handoff /path/to/ml2-handoff-2026-11-10
python -m a2_data_pipeline.gtfs_inputs moscow-urban-2026-11-10.2 \
  --route 141500134 --from 2026-11-05 --to 2026-11-30 \
  --output data/processed/normalized-transit/moscow-c894-nov2026
```

Путь данных можно задать `--root` или `A2_DATA_DIR`; в нём должны быть принятые
bundle и versioned manifests. `gtfs_inputs.load_bounded_gtfs(...)` возвращает
`NormalizedGtfs(accepted_data: AcceptedData, timetable: Timetable, report: dict)`.
CLI сохраняет `accepted-data.json`, `timetable.json`, отчёт и SHA256-манифест в
новый immutable каталог. Backend может загрузить их каноническими
`AcceptedData.model_validate_json` и `TypeAdapter(Timetable).validate_json`.
Это входы для server-owned `waydex-engine-inputs/1`, а не публичный HTTP-запрос.

Дочерний snapshot получает детерминированный ID по родительскому AcceptedData,
SHA256 GTFS, правилам, маршрутам и датам. Родительский bundle не изменяется;
население, QA исходного принятия и незакрытые области покрытия наследуются.
QA дополняется проверками нормализации, дата исходного принятия не выдаётся за
новую полевую проверку. Физические `gtfs-stop:*` добавляются отдельными узлами
с координатами и evidence GTFS. Они не отождествляются с проекциями на пешую сеть.
Сохраняются целые цепочки остановок, service-day секунды больше 86400,
календарные исключения, IANA timezone и датированные идентичности рейсов.
Перевод в UTC соответствует GTFS «полдень минус 12 часов», включая переход DST;
отсутствующие pickup/dropoff используют стандартную семантику GTFS.
Первичный источник этих правил — [GTFS Schedule Reference](https://gtfs.org/documentation/schedule/reference/).

Ограничение — до четырёх маршрутов и 31 сервисного дня, максимум 10 000
датированных рейсов. 4 ноября, выход за принятый период, потерянные при repair
ограничения посадки и маршруты с неоднозначными задвоенными отправлениями
отклоняются. Если физическая остановка не принята, исключается весь рейс с
причиной в отчёте. Пешие подходы и пересадки не выдумываются; флаги полноты
публичной сети остаются false. Справка частоты Калининграда не становится рейсами.

Реальная проверка маршрута с894 (`141500134`) за 5–30 ноября: 275 исходных
идентичностей рейсов, 3730 датированных исполнений, 54 физические остановки,
ни одной исключённой цепочки. Для 10 ноября 09:00 МСК, остановки `1010377` → `6930`,
движок нашёл 2280 с = 300 с ожидания + 1980 с движения без пересадки.
Это best-known время в ограниченном расписании: `minimum_proven=false`,
индекс отсутствует, полный рейтинг недоступен. Такая пара остановок не заменяет
городскую категорию учреждений или индекс доступности населения.

`data/manifests/qa/full-product-source-inventory-2026-11-10.json` фиксирует
факты всех четырёх профилей, pipeline и сценариев, а также наличие immutable raw
в проверенном checkout после восстановления handoff. Наличие accepted snapshot
не означает наличие исходных raw: исходные JSON Москвы, PBF и реестры требуют
своего архива с теми же SHA256. Повторная загрузка изменившегося URL не заменяет
такие байты. Принятые точки четырёх трубопроводных терминалов Новороссийска
не доказывают направленное соединение, продукт или сопоставимые V/Q.

### Связи с пешеходной сетью и ОТ Москвы — версии `2026-11-10.2`

`.2` заменяют `.1` (ревью ML1): правила связей `walk-connector-geometry-v2` учитывают заборы, стены и ворота с доступом. В `.1` забор с `foot=no` не останавливал связь, поэтому `.1` не использовать; они оставлены, так как опубликованное не меняется.

Движок ML1 подтверждает связь точки или объекта с входом на сеть (`WalkConnector`) и без неё блокирует пару (`CONNECTOR_UNCONFIRMED`). `a2_data_pipeline.supplements` выпускает новую версию bundle из предыдущей: те же коллекции плюс связи, а для Москвы — остановки GTFS.

| | Калининград | Новороссийск | Москва |
| --- | --- | --- | --- |
| Связей проверено | 680 | 615 | 11 983 |
| Проходимы (`traversable=true`) | 489 (72 %) | 533 (87 %) | 7 311 (61 %) |
| Unknown: барьер без ворот / закрытые ворота / ворота без тегов доступа | 136 / 2 / 2 | 15 / 0 / 0 | 3 548 / 225 / 352 |
| Unknown: чужое здание / ж/д / вода / магистраль / >500 м | 70 / 5 / 3 / 0 / 3 | 54 / 7 / 3 / 5 / 10 | 1 208 / 16 / 10 / 27 / 13 |
| ML1 считает подтверждёнными (при проверочной скорости) | 350 из 478 | 455 из 516 | 4 163 из 5 832 |

Больше всего связей упирается в ограждения школ, детсадов и поликлиник: территория огорожена, а ворота в OSM отмечены не везде. Такая связь — unknown, а не «прохода нет».

ОТ Москвы в `moscow-urban-2026-11-10.2`:
- `manifest.timetables` — ссылка на GTFS по sha256 с окном, неизвестными датами (4 ноября) и ограничениями;
- `transit_stops` — 13 785 используемых рейсами остановок в 10 км от границы, привязанных к пешеходной сети: 13 751 принята, 34 дальше 150 м — в карантине;
- `coverage` — `public_transport` partial на ноябрь.

В `AcceptedData` v2 ничего из этого нет (там нет коллекций связей и остановок, а рейсы контракт ждёт внутри snapshot), поэтому v2 у новых версий тот же, что у `09.x`.

## Правила, которые проверяет код

- **Неизвестное не равно нулю.** `population_status` бывает `estimated`, `zero` или `unknown`; при `unknown` поле `population` равно `null`.
- **Отсутствие требует scope.** `confirmed_absence` допускается только при `status=complete` своего scope.
- **Точки выборки.**
  - В каждой sampled-ячейке ровно одна точка, в excluded — ни одной, и у ячейки указана причина.
  - Точка стоит в центре квадрата, если центр попадает в здание. Иначе это ближайшая точка части здания внутри той же обрезанной ячейки. При равенстве выбирается меньший id здания.
  - Переноса между ячейками нет: точка и исходный центр лежат в рамке своего квадрата (`square_bbox`).
- **Вход на граф** (`access_nodes`, правила `osm-walk-network-v1`).
  - Это проекция точки на ближайшую пешеходную линию OSM из главной связной компоненты сети, поэтому вход не попадёт на оторванный кусок.
  - Ничья — в пределах 1 мм от минимума, её решает меньший id линии.
  - Расстояние до входа сохраняется в `access_distance_m` и не теряется из времени пути.
  - Аэропорт ставится на пассажирский терминал (`aeroway=terminal`), а не в центр лётного поля.
- **Население.** Население принадлежит исходной ячейке и считается по центроидам пикселей GHSL. Доли районов берутся из тех же пикселей и не превышают население ячейки (QA `district_population_not_doubled`).
- **Публичные категории.** Поликлиника, детсад, школа, колледж или вуз могут быть `accepted` только с `category_ownership.basis=registry` и `verification_state=verified`. Без такой сверки объект в карантине с причиной `OWNERSHIP_UNVERIFIED`.
- **Школы и детсады** (`klgd_education`). Перечни подведомственных учреждений на сайте администрации Калининграда, плюс координаты корпусов с её карты учреждений. Учредитель — город, поэтому собственность муниципальная.
  - Каждый корпус — отдельный объект: филиалы в разных местах ТЗ разрешает.
  - Кандидаты OSM привязываются к корпусу по правилам `registry-osm-match-v1`: номер совпадает — до 300 м; безымянный или типовой объект («Школа») — до 60 м; при разных номерах привязки нет.
  - Непривязанные кандидаты остаются в карантине: это частные и региональные учреждения или объекты со старыми номерами.
- **Поликлиники** (`tfoms39_trmo`, правила `trmo-polyclinic-rules-v1`).
  - Подразделение ТРМО ТФОМС входит, если оно не исключено из реестра, помощь амбулаторная и первичная врачебная, в названии есть «поликлин» (но не «консультатив»), а ОКФС 13 или 14.
  - «детск» в названии — детская поликлиника. Без «детск», но с профилями «терапия» и «педиатрия» — обе категории.
  - Подразделения одной категории по одному адресу — один объект.
  - Место берётся по адресу из OSM (`osm-address-match-v1`). Улица и дом должны совпасть, номер ±4 той же чётности допустим как приблизительный. Населённый пункт тоже должен совпасть: адрес Калининграда ищется внутри границы города, другой пункт — только по `addr:city`.
- **Колледжи и вузы** (`obrnadzor_accreditation`, правила `obrnadzor-college-university-rules-v1`). Открытые данные ИС ГА Рособрнадзора.
  - Берутся действующие свидетельства и приложения: организации региона и филиалы с адресом в городе.
  - Это колледж или вуз, если есть аккредитованное высшее образование или полное наименование — профессиональной или высшей образовательной организации.
  - Форма собственности берётся из ОПФ в полном наименовании: федеральная, региональная или муниципальная.
  - Не берутся частные организации, а также федеральные казённые (военные, ФСБ, МВД, ФСИН), специальные закрытые и социальные учреждения: это не места учёбы для жителей.
  - Корпуса в OSM привязываются к организации по названию (`edu-name-link-v1`): по аббревиатуре («БФУ», «КГТУ»), либо по отличительным словам, сверяя основы, — когда в названии OSM нет лишних слов и тип учреждения не противоречит.
  - Адрес из реестра даёт объект, если в 100 м нет привязанного корпуса той же организации.
- **Грузы** (`freight-osm-rules-v2`).
  - Порт ищется в границе города, где есть зарегистрированный морской порт (запись Росморпорта с регистрационным номером). Узел порта — портовая территория OSM (`landuse=harbour|port`, `industrial=port`, `man_made=container_terminal`) или объект со словом «порт» в названии («аэропорт» не считается). Без записи о порте они в карантине `SEAPORT_RECORD_MISSING`.
  - Объект, названный по оператору из перечня стивидоров, тоже кандидат в узлы. Оператор привязывается по отличительному слову («НУТЭП», «Цепрусс»). Росморпорт держит этот перечень в HTML-комментарии, на сайте его не видно. Поэтому evidence оператора — `unknown`, а объект, найденный только по перечню, в карантине `OPERATOR_LIST_UNPUBLISHED`.
  - Факты о порте (номер, мощности, упоминание причалов КТК) берутся только из видимого текста страницы.
  - Трубопроводный терминал: нефтяная площадка с «КТК», «Каспийск», «Шесхарис» или «ПНБ» в названии.
  - Ж/д станция всегда в карантине, пока грузовые операции не подтверждены.
  - Площадка: промзона OSM от 0,5 га или склад и производственное здание от 1000 м² вне промзон. Депо, очистные, котельные и то, что лежит внутри узлов, не считаются.
  - Подъезд: точка внутри контура, её проекция на ближайшую дорогу главной компоненты. Это не размеченные ворота.
  - Дорога для грузовика (`osm-road-network-v1`): автомобильные `highway` от `motorway` до `service` и `living_street`, без пешеходных путей и `track`. Решает самый частный тег доступа (`hgv` → `motor_vehicle` → `vehicle` → `access`), поэтому `hgv=no` закрывает улицу и при `motor_vehicle=yes`.
- **Справочник территорий** (`a2_data_pipeline.territories`, правила `ru-territories-rules-v1`).
  - Город — элемент Wikidata явного городского класса («город», «город России», «большой город», «мегаполис», «город федерального значения» и др.) со страной Россия. Замыкание по подклассам не берётся: оно приносит сёла и усадьбы.
  - Субъект города — ближайший субъект по текущим утверждениям «расположен в» (без даты окончания, не устаревшим); автономный округ ближе области. Если текущая цепочка обрывается — по всем утверждениям; ничья — город не ставится.
  - Пояс города — свой (IANA или смещение), иначе пояс субъекта; смещение переводится в представительную зону IANA (у российских зон одного смещения сейчас одинаковые правила).
- **Межгородские узлы** (`a2_data_pipeline.intercity_nodes`, правила `ru-intercity-nodes-rules-v1`, в v2 — автовокзалы OSM).
  - Станция — ближайший город справочника по текущим утверждениям «расположен в». Подъём останавливается на субъекте, поэтому станция села не становится узлом города, из которого управляют районом. Ничья — узел не ставится.
  - Аэропорт — у каждого города справочника, который он обслуживает (P931), иначе у города, где стоит.
  - Ж/д узел — станция или остановочный пункт с кодом ЕСР или «Экспресс». Здание вокзала без кода — часть станции, а не второй узел.
  - Автостанция — элемент класса «автостанция»; его подкласс «конечная остановка автобуса» — городские конечные, они не входят.
  - Не входят: грузовые, сортировочные и бывшие станции, закрытые объекты (P576/P3999, в том числе с неизвестной датой), военные аэродромы, аэродромы без IATA и ICAO, объекты без координат или без русского названия. Военный аэродром, который одновременно гражданский аэропорт (совместное базирование: Храброво, Братск), остаётся.
  - v2: автовокзал OSM — `amenity=bus_station` со словом «автовокзал» или «автостанция» в названии (как в городских bundle; остальное — городские конечные) внутри очертания города. Объекты OSM одного города ближе 150 м — один узел. Объект с тегом `wikidata` автостанции из Wikidata или ближе 300 м к ней в том же городе — тот же узел, к нему добавляются ссылки OSM.
- **Проход по OSM всей России** (`a2_data_pipeline.osm_national`, правила `osm-national-v1`). Полный индекс точек страны в память не помещается, поэтому выгрузка читается фильтрованными проходами: отношения → нужные им линии и линии с тегами → только нужные точки и точки с тегами.
  - Очертание города — отношение или замкнутая линия с тегом `wikidata` города справочника и `place=city|town` (чаще всего мультиполигон) или границей; связь — тег, а не название. Несколько очертаний города объединяются. Кольца, которые не замыкаются, попадают в отчёт и не чинятся.
  - Портовая территория — `landuse=harbour|port`, `industrial=port` (линии и мультиполигоны).
  - Результат привязан к sha256 выгрузки, правилам и списку городов так же, как кэш городского среза.
- **Связи с пешеходной сетью** (`a2_data_pipeline.supplements`, правила `walk-connector-geometry-v2`). Прямой отрезок от точки или объекта до его входа на сеть проверяется по слоям того же OSM-среза (sha256 PBF сверен).
  - Проходим (`traversable=true`), если не пересекает чужих зданий (своё — здание, на котором стоит точка, здание объекта в OSM и любое здание, где лежит сама точка), воды, наземной железной дороги (`rail`, `light_rail`, `narrow_gauge`, `monorail`; тоннели и мосты не считаются), магистралей (`motorway`, `trunk`) и не длиннее 500 м.
  - v2 (ревью ML1): не пересекает линейных барьеров (`barrier=fence|wall|city_wall|retaining_wall|hedge|guard_rail|jersey_barrier|cable_barrier|ditch`), кроме как через ворота этого барьера в пределах 10 м, открытые для пешехода: `foot=yes|designated|permissive` или `access=yes|permissive` без `foot=no`. Ворота с `foot`/`access` `no|private` или `locked=yes` закрыты; без тегов доступа — unknown. Барьеры читаются из того же PBF (sha256 сверен).
  - Иначе — unknown с причинами, но не «непроходим»: там может быть мост, переход или калитка.
  - Секунды ML2 не выдумывает: `walk_connectors()` считает их по скорости принятого пешеходного профиля Valhalla, которую ей передают с evidence. Без принятого профиля связь остаётся неподтверждённой.
- **Остановки ОТ** (`transit-stops-v1`). Остановки GTFS, которые используют рейсы, в 10 км от границы города привязываются к пешеходной сети так же, как точки и объекты. Дальше 150 м от сети — карантин. Сам GTFS лежит вне bundle и привязан по sha256 (`manifest.timetables`).
- **Морские порты РФ** (`a2_data_pipeline.seaports`, правила `ru-seaports-rules-v1`).
  - Основание узла — функция: зарегистрированный морской порт, где работает Росморпорт (видимый перечень на `/services/seaports/`). Регистрационный номер и мощности — из раздела порта на странице филиала, как опубликованы; число переводится в тыс. тонн или тыс. TEU в год («млн» ×1000, число без «тыс.» ÷1000). «нет» хранится как сказано, пустая подпись — unknown.
  - Город — город справочника с тем же названием (порт в реестре назван по месту; «Большой порт» и «Пассажирский порт» Санкт-Петербург — Санкт-Петербург). Название нескольких городов или не город — без привязки.
  - Место — характерная точка самой большой портовой территории OSM в очертании города; остальные территории там перечислены.
  - Принят порт с регистрационным номером, городом и местом; иначе карантин с причинами. Имена стивидоров из скрытого перечня не используются, хранится только его размер.
- **Ремонт GTFS** (`a2_data_pipeline.gtfs`, правила `gtfs-repair-v2`). Ничего не придумывается: остаются стандартные колонки GTFS, строки с битой ссылкой или нарушенным порядком удаляются, каждая потеря считается по причине.
  - С v2 (ревью ML1) исключения `calendar_dates.txt` сохраняются в архиве и применяются: тип 2 убирает сервис в этот день, тип 1 добавляет (и для сервиса, который есть только в исключениях). Строки с неверной датой, типом или повтором даты отбрасываются и считаются. Для фида без исключений v1 и v2 пишут одинаковый архив — оба наших московских фида (data.mos.ru и mdb-3226) исключений не содержат, sha256 не изменился.
  - Сервис календаря с неверными датами или флагами, остановка без координат, рейс с неизвестным маршрутом или сервисом — удаляются.
  - Строка stop_times с неизвестным рейсом или остановкой удаляется. Рейс сортируется по `stop_sequence` и удаляется, если последовательности повторяются, прибытие позже отправления, время идёт назад или осталось меньше двух остановок.
  - Праздники без `calendar_dates` восстановить нельзя — отчёт это фиксирует. Архив детерминирован: тот же raw даёт тот же sha256.
- **Население и покрытие растра** (ревью ML1, 10.11). Покрытие хранится отдельно от суммы: у ячейки `raster_pixels_total` и `raster_pixels_valid`. Пиксель nodata или за краем тайла (окно читается с заполнением nodata) делает ячейку unknown (`population=null`), а не нулём; ноль — только когда все пиксели валидны и равны 0. QA `population_raster_covered` (warn). В трёх пилотных городах внутри границы нет ни одного пикселя nodata (`data/manifests/qa/population-raster-coverage-2026-11-10.json`), так что нули в опубликованных bundle — настоящие.
- **Детсады Новороссийска** (`nvr_gorono`, правила `gorono-kindergarten-rules-v1`). Перечень подведомственных ДОУ Управления образования: из карточки берутся только официальное наименование и адрес (ФИО, телефоны, e-mail не читаются). Учредитель — город, собственность муниципальная. Место — адрес в OSM; адрес без населённого пункта считается городским, потому что перечень городской. Кандидаты OSM привязываются по правилам `registry-osm-match-v1`.
- **Адреса.** Индекс перед населённым пунктом («353900 г.Новороссийск») и «г.» без пробела не мешают узнать город; номер дома в конце улицы («пр. Ленина 63») читается.
- **Справка частоты** (`gortrans39`, правила `gortrans39-frequency-rules-v1`).
  - Таблица остановки без trip_id: отправления разных остановок никогда не склеиваются в рейсы (IMPLEMENTATION). Строка — маршрут × остановка × тип дня: число уникальных отправлений, первое и последнее, максимум за час, медианный интервал.
  - Маршрут в карантине, если первая остановка повторяет список другого маршрута (`SHARED_TEMPLATE_TIMETABLE`) или все её списки — ровная сетка через 30 минут на круглых минутах (`REGULAR_GRID_TIMETABLE`).
  - Пустой список типа дня — unknown (`EMPTY_DAY_LIST`), не ноль отправлений.
  - Место остановки — OSM-остановки (`stops`) с теми же словами названия, если они в пределах 300 м друг от друга; иначе — те, у которых в `route_ref` есть номер маршрута; иначе координат нет.
- **Поликлиники Москвы** (`mgfoms_med_org`, правила `mgfoms-polyclinic-rules-v1`). Справочник медорганизаций МГФОМС (массив на странице сайта).
  - Входит запись (организация или филиал) с типом «поликлиника с прикреплением» и принадлежностью ДЗМ: собственник — город Москва, субъект РФ.
  - «Детское» население — детская поликлиника, «взрослое» — взрослая, оба — обе категории. Женские консультации не входят.
  - Место — координаты фонда; записи одной категории в одной точке — один объект. ФИО, телефоны и e-mail не читаются.
- **Корпуса школ Москвы** (`school-building-link-v1`, только для Москвы: школа там — комплекс корпусов).
  - Школа или детсад OSM с «Школа № N», «Лицей № N», «Гимназия № N» в названии — корпус государственной школы реестра с этим номером, если номер у одной школы города и до её адреса не больше 5 км.
  - «Детский сад № N» по номеру не привязывается: старые номера садов совпадают с номерами школ. Здание, уже занятое адресом другой школы, не привязывается.
  - Номер учреждения после «№» читается до четырёх цифр; голое число — до трёх, чтобы не путать с годами.
- **Один объект — одна запись в категории.** Организации по одному адресу (институты РАН в одном здании) дают один объект с evidence всех организаций. QA `destination_identity_unique` (fail) не пропускает повтор объекта в категории — то же правило есть в контракте v2.
- **Объекты за границей.** Объект за границей города разрешён и помечается `inside_city_boundary=false`. Пример — аэропорт Храброво.
- **Неизменяемость.** Bundle публикуется атомарно (staging → rename) и не перезаписывается. `load_bundle` при каждом чтении сверяет sha256 всех коллекций и QA-отчёта, число строк и все ссылки.
- **Кэш среза OSM.** Срез привязан к входу: в `extract_meta.json` записаны sha256 PBF, `dataset_id`, версии правил пешеходной и дорожной сети и список таблиц. С 10.11 (ревью ML1) у каждого входа свой неизменяемый каталог `data/processed/<город>/osm/<ключ>`, где ключ — хэш sha256 PBF, правил, границ и рамок (`osm.ensure_extract`). Срез пишется во временный каталог и публикуется одним атомарным переименованием, поэтому две сборки не могут оставить метаданные одного источника над таблицами другого; при гонке за один вход проигравшая сборка берёт уже опубликованный каталог. Так же публикуется проход по всей России (`osm_national.ensure_national`, `national-<ключ>`).

Нужно решить BACKEND:

1. **Районы.** `TerritoryLevel` допускает только `city|region`, а у `PopulationCell` нет долей районов. Районы ML2 отдаёт как `AreaOption` через `registry_options()`. Но для агрегатов районов без удвоения (PRODUCT_SPEC §2) нужны доли населения ячеек по районам.

2. **Категория без scope.** Объекты в карантине в snapshot не попадают. В этом snapshot у всех девяти категорий есть scope, но в других городах его может не быть. Нужно подтвердить: отсутствие scope по категории означает `DATA_UNAVAILABLE`, а не `NO_FEASIBLE_ROUTE`.

   - Предложение: `Destination.access_distance_m`.
   - Критерий: путь до объекта включает расстояние от входа до объекта.
4. **`calendar_version` обязателен,** а расписаний в этом snapshot нет. Сейчас ML2 передаёт `not_collected`. Предложение: сделать поле nullable или явно договориться о значении `not_collected`.

Воспроизведение с исходным PBF SHA256
`769a6a6ac552b534057f2480b88f1c2d0709636761ab6d08483efe69c1e97b69`:

```bash
uv sync --frozen --all-packages
.venv/bin/python -m a2_data_pipeline.school_audit \
  --bundle-id kaliningrad-urban-2026-11-10.2 \
  --pbf /path/to/kaliningrad-261107.osm.pbf \
  --extract-root /path/to/separate-runtime/osm \
  --official-list /path/to/immutable/klgd-schools-all.html \
  --output /path/to/audit.json
.venv/bin/python -m a2_data_pipeline.school_revision \
  --official-list /path/to/immutable/klgd-schools-all.html \
  --provenance /path/to/immutable/klgd-schools-all.provenance.json \
  --audit-report /path/to/audit.json
```

Повторная публикация `.3` отклоняется; для воспроизведения в отдельный data root
поместить `.2` и manifests, затем задать `A2_DATA_DIR`. Provenance JSON содержит
`url`, `retrieved_at` с timezone и `sha256`. Свежая HTML-страница может отличаться:
builder намеренно требует проверенный hash, а не автоматически принимает drift.

не соответствует pinned requirement. Manifest/lock не изменялись.
