# AssistantResult

ML2 формирует результат в оркестраторе. BACKEND передаёт его по HTTP, FRONTEND показывает текст, уточнения и ссылки, ML2 использует проверяемый журнал в evals. Расчёт выполняется engine по публичным интерфейсам.

Обязательные поля — `schema_version`, `request_id`, `trace_id`, `status`, `model`, `created_at`, `answer`, `missing_fields`, `tool_calls`, `claims`, `source_ids`, `run_refs`. `model` содержит фактически использованный ID модели или `null`, если ответа модели не было. `created_at` в UTC. `answer` — текст или `null` при недоступности. Времена поездок и единицы в ответе наследуются из инструментов, P1 отображается в `Europe/Kaliningrad`, длительность в минутах и разность индекса в пунктах. `run_refs` включают версии набора, профиля и алгоритма использованных расчётов. Массивы могут быть пусты при уточнении или ошибке.

Каждый `tool_call` содержит `call_id`, `tool_name`, `tool_schema_version`, `status`, `result_ref` и `error_code` (последние два nullable согласно исходу). `result_ref` разрешается в фактически возвращённый результат, сохранённый с теми же версиями и ссылками на источники. `claims` связывает каждое фактическое или числовое утверждение с `call_id`, полем результата и применимыми `source_ids`. Уточнение и допущения маркируются отдельно. Для клиента доступны только разрешённые поля журнала и источники.

| `status` | Смысл |
| --- | --- |
| `ok` | Проверенный ответ, фактические утверждения подтверждены результатами инструментов. |
| `clarification_required` | Нужны обязательные параметры, `missing_fields` содержит конкретные поля. Расчёт с неполным запросом не запускался. |
| `partial_data`, `missing_data`, `no_path_in_window` | Передан соответствующий статус расчёта и его границы. |
| `model_unavailable`, `tool_failed` | Ответ не может опереться на валидный результат. Ошибка сохранена в трассировке. |

Инструменты первого среза — `get_profile` с точной версией профиля и `simulate_scenario` с аргументами `ScenarioRequest`. Сервер ограничивает список инструментов и число вызовов, валидирует их строгие схемы и предметные ограничения. Неизвестный инструмент даёт `tool_not_allowed`, несоответствие схеме — `invalid_tool_arguments`, ошибки engine сохраняются по контракту. Неподтверждённое утверждение отклоняется с `ungrounded_answer`. Свободного SQL, исполнения кода и изменения базовых данных среди инструментов нет. Внешний текст используется как данные и не меняет разрешения инструментов.
