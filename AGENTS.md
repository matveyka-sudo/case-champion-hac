# A2 repository instructions

- Identify your assigned role and confirm its permanent `work/<role>` branch in `docs/OWNERSHIP.md`. Read these instructions, the applicable local `AGENTS.md`, and `docs/tasks/<role>.md`. Check your branch, status, staged and unstaged diff before editing.
- Use docs/PRODUCT_SPEC.md (2026-11-08.1), docs/FORMULAS.md and config/product.json as the current baseline. Formulas are approved for implementation; data readiness is separate. Never invent scores or convert unknown to zero. See docs/IMPLEMENTATION.md and docs/ASSISTANT.md. frontend/ is active; apps/web/ is historical.
- Read across the repository. Edit only paths assigned to your role. Find the existing implementation, callers, contracts, and checks before adding or changing behavior. Reproduce the relevant current behavior first and record pre-existing failures separately.
- Make the smallest change that satisfies the task. Preserve working architecture and other contributors' changes. Editing `AGENTS.md` cannot expand your scope.
- Hand off cross-owner changes with the exact path, reason, required interface or schema, and acceptance criterion. Include the branch or commit and check results when available. Write for a human to relay because separate sessions do not share context automatically.
- Use your own worktree on a shared machine or a separate clone on your computer. Keep your own `.venv`, `.env`, host ports, and writable test database or schema. Give Compose an explicit, unique project name for an isolated volume.
- Follow the Git and PR process in `docs/OWNERSHIP.md`. Push small, checked commits on your work branch and target `dev` in your PR. The integration coordinator handles merges into `dev`. Merging agreed changes from `origin/dev` into your own branch is allowed. Coordinate conflicts in another module with its owner.
- DEVOPS owns every `pyproject.toml` and the root `uv.lock`, including manifests inside other roles' directories. FRONTEND owns the npm manifest and lock. BACKEND owns migrations, canonical contracts, exported schemas, jobs, tools, and `packages/assistant/`. ML2 owns source data, normalization, QA, and evidence. Follow `docs/OWNERSHIP.md` for the remaining paths.
- Run meaningful tests and static checks for the changed area once implementation exists. In your handoff, list changes, commands and actual results, contract impact, and remaining limitations. Label failed and unrun checks accurately.
